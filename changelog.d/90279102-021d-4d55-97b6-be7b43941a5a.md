### Changed

- **Per-run cache caps stop at 15 GiB on large worker volumes (#4576).**
  `UZI_RUN_CACHE_CAP_MAX_BYTES` (default 15 GiB, `off` disables it) now bounds the soft cache cap, so a 100 GiB volume caps at 15 GiB instead of 25 GiB, at the cost of more Go cache rebuilds, possible whole-module-cache drops on a trim and more uncounted preventive parks; it is a mitigation, not a within-turn bound. Hosted deployments can set it and the cap fraction through the chart values `workers.runCacheCapMaxBytes` / `workers.runCacheCapFraction` (strings only, empty by default, relayed verbatim by the controller only when nonempty, so a change rolls the fleet once); `docker-compose.yml` now passes both through, so an existing `.env` `UZI_RUN_CACHE_CAP_FRACTION` line now takes effect.
