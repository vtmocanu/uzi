### Changed

- Hibernation wakes recheck claim provenance before recording demand and release obsolete wake rows, so a claim/requeue cannot leave a Codex run waiting on a worker that cannot claim it.

- **A Codex run that has been claimed is held for the worker that last ran it (#4476).**
  No fall-open path (stale-requeue grace, affinity ceiling, deleted worker, cross-check) offers it to another worker, and runs already at generation 1 or later at upgrade have no record, so they are held at their next fresh claim: cancel them with `uzi run cancel`. Run health shows "held for worker NAME" or "predecessor provenance unavailable", which now count as genuine waits for `queue.waiting` and `fleet.capacity`; rolling the api back leaves claims ungated until re-upgrade.
