### Changed

- **The api now caps each database connection's prepared-statement cache at 128 statements (#4591).**
  pgx's default is 512 and each cached statement holds its plan in the PostgreSQL backend; in the measurement harness the cap cut steady backend heap by 16.7% with JIT off and 3.8% with JIT on, with flat hot-path latency, and the production saving is unmeasured. A `statement_cache_capacity` in `DATABASE_URL` overrides it (512 restores pgx's default; never 0), and a working set above about 126 distinct statements per connection makes the worker claim re-prepare, so raise it there.
