### Added

- **Admins can hibernate and wake idle hosted workers (#4205).**
  Hibernating scales the worker's Deployment to 0 and keeps its row, join-token Secret and volumes; it is off by default behind `worker_hibernation_enabled`, an admin can wake a worker, disabling the setting wakes all, and a queued run no awake worker can claim wakes one capable hibernated worker of its owner (one wake per run, no ephemeral worker for it meanwhile, up to 15 minutes); downgrading needs the setting off, all workers awake, then the api stopped and migrations 00439, 00438, 00437 and 00436 rolled back before an older api starts (the rollback of 00436 refuses while any worker is not awake; 00437 drops its transient wake records). A worker that a queued run just woke cannot be hibernated again until that run leaves the queue. A run waiting for a waking worker shows its owner "your worker is waking from hibernation", and a new instance-scoped `fleet.hibernation_wake` Admin health check warns when a wake failed or is unconfirmed after 15 minutes.
