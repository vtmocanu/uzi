### Added

- **Runs receive their repo's variables as environment variables (#4416).**
  Lead-agent runs on both harnesses get the enabled variables in every command at the lowest precedence, with secret values redacted from output (raw, JSON, HTML-safe, percent and base64 forms, and every line of a multi-line value of 8 or more characters except PEM armour and whitespace-only lines, so structural lines of a secret file are masked too, and the plan-turn changed-file list, capability evidence paths and proposal repo fields) and every publish searched for them (a run holding a multi-line secret gets no preserved patch, `multi_line_secret`, and its work stays recoverable with `uzi run export`), file paths of outgoing commits included, failing closed (a path scan that cannot finish is `path_scan_incomplete`, and the publish is withheld or the push blocked); saving a secret that would push the repo's secret value bytes past 116,959 (the bound counts the logger's JSON-escaped copies) is refused with 409 `env_forms_budget` (a repo already above it can shrink but not grow), a claim whose secret forms still pass the form cap fails before any work as `run_env_forms_over_budget`, `AWS_ENDPOINT_URL_STS`, `AWS_ENDPOINT_URL_SSO` and `AWS_ENDPOINT_URL_SSO_OIDC` names are refused like `AWS_ENDPOINT_URL`, and the feature needs a worker that reports `run_env_v1`, so a lead-agent run whose repo has an enabled variable is not claimed by an older worker.
