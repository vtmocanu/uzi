### Added

- **Runs receive their repo's variables as environment variables (#4416).**
  Lead-agent runs on both harnesses get the enabled variables in every command at the lowest precedence, with secret values redacted from output (raw, JSON, HTML-safe, percent and base64 forms, and each qualifying line of a multi-line value) and every publish searched for them, file paths of outgoing commits included, failing closed (a path scan that cannot finish is `path_scan_incomplete`, and the publish is withheld or the push blocked); saving a secret that would push the repo's secret value bytes past 207,253 is refused with 409 `env_forms_budget`, a claim whose secret forms still pass the form cap fails before any work as `run_env_forms_over_budget`, `AWS_ENDPOINT_URL_STS`, `AWS_ENDPOINT_URL_SSO` and `AWS_ENDPOINT_URL_SSO_OIDC` names are refused like `AWS_ENDPOINT_URL`, and the feature needs a worker that reports `run_env_v1`, so a lead-agent run whose repo has an enabled variable is not claimed by an older worker.
