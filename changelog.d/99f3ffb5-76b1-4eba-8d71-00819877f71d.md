### Added

- **Custom provider runs are activated for every install, with the Claude CLI redirect risk accepted (#4505).**
  Workers now advertise `claude_provider_v1` by default (no switch), so a run bound to a custom provider starts instead of queueing; the loopback relay that would stop redirects (#4496) is parked. The pinned Claude CLI follows gateway redirects, so a gateway that answers with one can make the CLI re-send the key to another path on the same host under both auth styles and the request body (prompts, plus code and tool output the agent read) to any Location host, and with `x_api_key` auth the key goes cross-host too, while Bearer drops Authorization cross-origin. The operator allowlist (`UZI_PROVIDER_ALLOWED_BASE_URLS`) is the only control on where provider traffic starts, so allowlist only gateways you trust not to redirect and prefer Bearer auth. The worker redacts the provider key and its encoded forms from model, review and summary output, run and chat text, PR descriptions and other forge text, and blocks any forge upload (branch push, checkpoints, held publication) whose objects carry it, keeping the work local (`push_secret_blocked`); recovery-bundle uploads to the uzi API custody archive are not scanned, and a provider run whose new objects exceed the scan caps has checkpoints withheld and its final push refused. Rollout: the release helper bumps the chart's worker image pin, but operator image overrides and Compose or separately run workers must be updated by their operator; an old worker never claims a provider run, which stays queued with "no worker that supports model providers is online", and an old ephemeral worker bound to one is reaped and re-provisioned, with churn that is not bounded while an old image override remains. See ADR-4320 and docs/providers.md.
