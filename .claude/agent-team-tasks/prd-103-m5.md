From the design wave; these are frozen unless the auditor's critique moves one.

- **Taskfile shape.** Repo-wide checks get slot-first names with a **subject**, not a component: `lint:shell`, `lint:yaml`, `lint:formula`, `scan:secrets`. Add **`gate:repo`** composing the four, and give `gate:` a fifth dependency on it, **first** in the list (repo-wide checks are cheap; matches the cheap-first rule `gate:web` already states). **This closes a real hole**: `task --dry gate` enumerates 21 targets and the composed `lint` target is **not** among them — `gate` calls `gate:{api,controller,web,agent}`, each naming its slots individually. The Taskfile's own `lint:` comment tells M5 to append `lint:shell`/`lint:yaml` "to this same list", and following it literally produces two targets that `task gate` never runs. **The definition of done is "reachable from `task gate`", never "runs from a task target".**

A `# shellcheck shell=busybox` directive is *truer* but re-scopes every check on that file for a three-finding problem. **RE-AFFIRMED #4 against the auditor's stated preference, and the reason is now measured rather than argued.**

*The argument #3 gave was non-discriminating and should not have decided anything.* It was the auditor's second-order note — if the shebang or base image ever changes, `[ -O x ] && chmod` on a shell where `-O` is undefined **skips the chmod silently**, because POSIX exempts the left of an AND-list from errexit so `set -eu` does not fire. That hazard is real and worth a comment at the three sites, **but it applies to BOTH candidate forms equally**: a `disable=SC3067` comment and a `shell=busybox` directive both go on suppressing after a shebang change. A reason that does not separate the options cannot choose between them.

*The discriminator, measured by the lead 2026-08-03 at shellcheck 0.11.0:* **a `shell=` directive OVERRIDES the shebang.** A `#!/bin/bash` file carrying `# shellcheck shell=sh` is checked as POSIX sh and flags bash arrays (SC3030); the identical file without the directive is clean (rc=0 vs rc=1). So the two forms fail differently after a shebang change: `shell=busybox` keeps asserting busybox **for every rule across the whole file**, checking it as something it is no longer is, while three `disable=SC3067` comments suppress **one rule at three lines** and leave shellcheck tracking the real shebang for everything else. The narrower lie wins.

*The auditor's evidence is accepted and does not bear on this.* It verified the directive **works** at 0.11.0 with a good control — `shell=nosuchshell` is rejected (rc=1) rather than silently ignored, so a green under `shell=busybox` means the dialect was understood.
