## Hard constraints inherited from M1–M4

Not optional, and each has already cost this PRD a round:

- **`.gate_needs` and `.publish_needs` enumerate jobs BY NAME** (carry-forward item 2). Every lint-stage job M5 opens must be added to both. A job missing from `.publish_needs` means a `v*` tag publishes every image and the OCI chart to Harbor while that job is failing. **M5 inherits this in full** — its checks are repo-wide and cannot fold into a per-toolchain `validate:*` job. Verify by parsing, never by grepping.
- **The `lint` stage already exists and already has jobs** (`lint:api`, `lint:controller` from M3). M5 appends; it does not create the stage.
- **The CI job provides the tool, never devbox** (Decision 7). Options in preference order: a pinned `go run pkg@vX.Y.Z` inside the already-pinned `golang:1.26` (M3's precedent, and how `govulncheck` should arrive), a digest-pinned official image, an npm devDependency installed by the existing `npm ci`, or a version- and sha256-pinned `before_script` fetch.
- **A new devDependency silently breaks every existing checkout's gate** (carry-forward item 12), and in `agent/` the required remedy collides with the documented `agent-browser` host-wide clobber. If M5 adds one, the safe form is `npm install --ignore-scripts --save-dev --save-exact <pkg>@<version>`, and it owes a `docs/dev-conventions.md` line.
- **Taskfile bans**: no `sources:`/`generates:`/`status:` on any gate target, no `dotenv:`, no `includes:`, no dynamic root `vars:`, and never an unquoted variable spliced into a `cmds:` line. npm targets **delegate** to a `package.json` script rather than reimplementing the command.
- ~~**Recipes live in `Taskfile.yml` and nowhere else** (Decision 9).~~ **FALSE — CORRECTED 2026-08-03 #2, and it pointed the coder away from the design M5 itself motivated.** Two committed gate recipes are deliberately not in `Taskfile.yml`: `scripts/deadcode-gate.sh` and `scripts/assert-chart-render.sh`. The reason recorded at `Taskfile.yml`'s `deadcode:api` target **is M5's own**: *"A SCRIPT, NOT AN INLINE RECIPE, AND THE ARGUMENT IS M5's. PRD #103 M5 adds `shellcheck` over `git ls-files '*.sh'`, so a committed script gets LINTED and an inline Taskfile recipe gets nothing — yamllint checks YAML, not shell embedded in a `cmds:` string."* Decision 9 is about the gate **command appearing once** (`CLAUDE.md` and the paste-block name targets, not command lines); it is not a ban on scripts. **Non-trivial shell M5 adds belongs in a committed `scripts/*.sh`, precisely so M5's own checker sees it.**
- ~~**`exit 2` = instrument broken, `exit 1` = there are findings.**~~ **UNACHIEVABLE FOR THREE OF THE SIX — CORRECTED 2026-08-03 #2.** `go run` flattens every nonzero exit to **1** (measured: a program calling `os.Exit(3)` gives rc=1 under `go run`, rc=3 as a binary), so govulncheck's own convention of 3=vulns-found collapses under Decision 7's preferred provisioning route — this is already live in M3's shipped golangci-lint targets. And `yamllint --strict` **inverts** the convention (2 = warnings only, 1 = errors), while **without `--strict` yamllint exits 0 while printing findings** — the oxlint severity trap in a new tool. Keep the convention where the recipe controls its own exit; state explicitly where it cannot.
- **The devDependency constraint is now LIVE, not inert.** It was listed speculatively; the vitest ruling below makes it real. `npm install --ignore-scripts --save-dev --save-exact` is the safe form, and in `agent/` an unguarded install is the documented host-wide `agent-browser` clobber.
- **Give a new job its own `cache:` prefix** if it builds something the jobs sharing that key do not (carry-forward item 6).
- **The three fail modes** (carry-forward item 3) — fail-open, fail-loud-but-misleading, silent no-op — each need a different fix. Every check M5 adds should be classified against them before it ships. `exit 2` = instrument broken, `exit 1` = there are findings; `task`'s own rc is 201 for both, so the distinction lives in the recipe.

## Design rulings — 2026-08-03 #2

From the design wave; these are frozen unless the auditor's critique moves one.

- **Taskfile shape.** Repo-wide checks get slot-first names with a **subject**, not a component: `lint:shell`, `lint:yaml`, `lint:formula`, `scan:secrets`. Add **`gate:repo`** composing the four, and give `gate:` a fifth dependency on it, **first** in the list (repo-wide checks are cheap; matches the cheap-first rule `gate:web` already states). **This closes a real hole**: `task --dry gate` enumerates 21 targets and the composed `lint` target is **not** among them — `gate` calls `gate:{api,controller,web,agent}`, each naming its slots individually. The Taskfile's own `lint:` comment tells M5 to append `lint:shell`/`lint:yaml` "to this same list", and following it literally produces two targets that `task gate` never runs. **The definition of done is "reachable from `task gate`", never "runs from a task target".**
- **Fold, do not open, for the two checks that have a component.** `npm audit` → `validate:web` / `validate:agent`, which already run `npm ci`. `govulncheck` → `lint:api` / `lint:controller`, which already carry the `lint-` cache prefix for exactly the GOCACHE reason govulncheck needs. **Zero `.gate_needs`/`.publish_needs` edits for either.**
- **One new CI job, not four**, for the genuinely component-less checks (shellcheck, yamllint, gitleaks, ruby): `lint:repo` on a single digest-pinned image. Each additional job name is another two-list edit and forgetting one is this repo's signature failure shape. **`.gate_needs` 12→13, `.publish_needs` 14→15** — today's membership parsed (not grepped) as 12 and 14, delta exactly the two `publish:assert-*`. Note carry-forward item 2 says "M3 moved `.gate_needs` 9→11"; that is stale, the parse and `.gitlab-ci.yml`'s own comment both say 12 and 14.
- **Image warning, unverified and the coder must check it**: `koalaman/shellcheck:*` is reported to be `FROM scratch` with no shell and therefore unusable as a GitLab job image; `koalaman/shellcheck-alpine` is the one with a shell. No CI image this pipeline currently uses ships any of the four tools.
- **Ship shellcheck at `--severity=warning`, not `error`.** The `error` tier catches nothing here. Two source edits get `warning` green on the full tracked set: quote the `done` argument at `e2e/run-e2e.sh`'s `wait_disposition "$F_REVIEW" "$B6_CAT" "$B6_TGT" done` call site (SC1010 false positive — `done` is the WANT positional, the function signature is `local review="$1" cat="$2" tgt="$3" want="$4"`), and declare the busybox dialect on `agent/templates/entrypoint.sh`. **Prefer the dialect declaration over three `# shellcheck disable=SC3067` comments**: the file genuinely runs under busybox, so a `# shellcheck shell=busybox` directive states a truth rather than silencing a class, and it keeps SC3067 live everywhere else. Verify the directive form works at the pinned version before relying on it.
- **SC3067 is NOT live, and both validators established it independently.** `entrypoint.sh` is `#!/bin/sh`, shipped by both worker Dockerfiles on the same digest-pinned `node:22-alpine`, exec-form `ENTRYPOINT`, and `render.go` sets no `command:` so k8s uses the same interpreter. In that image `/bin/sh` is busybox 1.37.0 and `test -O` works — with a control proving the probe *could* have detected an unsupported operator (`[ -Q dir ]` → rc=2 "unknown operand").
- **🔴 `git ls-files '*.sh' | xargs shellcheck` IS FAIL-OPEN ON macOS AND FAIL-CLOSED IN CI.** With an empty list: BSD xargs never runs the command and exits **0**; GNU 4.10.0 and busybox both exit **123**. Same recipe, opposite verdicts, and the lying half is the contributor's — Success Criterion 1's exact failure mode. **Capture the list into a variable with `|| exit 2`, assert it non-empty (`exit 2`), then invoke** — the `fmt-check:api` assignment shape, reused for its second property rather than copied for its first. Applies identically to yamllint and `ruby -c`. *(The lead's own scouting command had this defect.)*
- **`ruby -c` needs a version guard.** `/usr/bin/ruby` on stock macOS is 2.6.10 and the formula uses the Ruby ≥3.1 shorthand hash value `ldflags:`, so the naive target is **red for every contributor** and the tempting "fix" is downgrading a correct formula. Assert `RUBY_VERSION >= 3.1` and `exit 2` (instrument broken) rather than running the check. Also: `ruby -c` on a **missing** file also exits 1, so it cannot distinguish "bad file" from "no file" — assert existence separately. And it is **syntax-only**: it cannot see a broken Homebrew DSL, and `publish_brew` `sed -i`s the `tag:` line before pushing, so the check validates the pre-sed source rather than the shipped artifact. Say so in the MR.
- **yamllint needs a committed `.yamllint`; defaults give 635.** Widen the scope beyond the PRD's `.gitlab-ci.yml` + `deploy/values/` to **every tracked `*.yml`/`*.yaml` except `deploy/chart/templates/`** (Helm templates are not valid YAML: 239 findings, the first a hard syntax error). That is 10 files and **2 findings** under a relaxed config that keeps `key-duplicates` and `syntax` at error. The wider scope picks up `deploy/chart/values.yaml` and `Chart.yaml` — which ship to Harbor in the OCI chart and carry the Model-B version/appVersion — plus `Taskfile.yml`, the one file in this repo with a *recorded* YAML parse failure (a bare `: ` inside a `desc:`, rc=109).
