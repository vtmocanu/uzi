## Requirements

### R1 — the recipe must NAME the drifted files when it fails

`gofmt -l` **exits 0 whether or not it lists anything** — `CLAUDE.md` documents
this trap and the `&&` form that fires unconditionally. The PRD's fix,
`test -z "$(gofmt -l .)"`, gates on output correctly **but swallows the
filenames**, and M2's own calibration criterion requires the gate to redden
*and name the file*. So the target must both print and fail. Something in the
shape of:

```sh
out="$(gofmt -l .)"; [ -z "$out" ] || { echo "$out"; exit 1; }
```

Confirm your chosen form actually prints under `output: prefixed` before
believing the calibration.

### R2 — Taskfile targets

`fmt-check:api` and `fmt-check:controller`, each with `dir:` set the way the
existing `vet:*`/`build:*` targets do, wired into `gate:api` and
`gate:controller` respectively. Decide and record whether a composite
`fmt-check` (both modules) is worth adding — the PRD's prose says "`task
fmt-check`" but Decision 2's per-component composition argues for the split.
State the choice and the reason in the MR.

Obey the Taskfile header's four bans verbatim — in particular **no `sources:`**,
which would let a fingerprinted `fmt-check` print `up to date`, exit 0 and check
nothing.

Each load-bearing thing gets an inline comment naming why, matching the file's
existing convention. The exit-0 trap in R1 is exactly such a thing.

### R5 — the liveness control (Success Criterion 8)

Introduce a deliberate misformat in a scratch file under `api/`, run
`task fmt-check:api`, confirm it **reddens and names that file**; restore and
confirm green. Repeat for `controller`. Record both in the MR description.

`CLAUDE.md`'s rule applies verbatim: *a control that produces no output is not a
control.* A green run with no named file proves nothing.

### R7 — gofmt version parity between local and CI

Unverified and worth one check: the baseline above was taken with local
`go1.26.5`; CI's `.go_job` runs the digest-pinned `golang:1.26` image, whose
patch level is not necessarily the same. `gofmt`'s output is stable across
patch releases in practice but is not contractually so, and a disagreement here
produces a gate that is green locally and red in CI (or worse, the reverse).
Establish what the image's `go version` actually is and say so in the MR.
