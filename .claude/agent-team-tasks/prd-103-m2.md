## Requirements

### R1 — the recipe form is settled, and BOTH reasons must be in its comment

**Use the assignment form.** Measured by the lead, `task` 3.51.1, `output: prefixed`:

| tree | form | RC | stdout |
|---|---|---|---|
| drifted | `out="$(gofmt -l .)"; [ -z "$out" ] \|\| { echo "$out"; exit 1; }` | 201 | names the files |
| drifted | `test -z "$(gofmt -l .)"` | 201 | **empty** |
| **non-parsing Go file** | assignment form | **201** (`exit status 2`) | the parse errors |
| **non-parsing Go file** | `test -z "$(...)"` | **0 — GREEN** | the parse errors |

Two independent reasons, and the second is the stronger one the PRD does not have:

1. `gofmt -l` **exits 0 whether or not it lists anything** (`CLAUDE.md` documents
   this), so the gate must be on the OUTPUT. The PRD's `test -z "$(gofmt -l .)"`
   gets that right but **swallows the filenames**, and M2's calibration requires
   the gate to redden *and name the file*.
2. **The PRD form fails OPEN on a Go file that does not parse.** `gofmt` exits 2
   and writes to stderr, so `$(…)` captures nothing and `test -z` is true. Under
   Task's errexit shell, an *assignment* whose command substitution fails aborts
   the script, while a substitution inside a *simple command* does not — that
   POSIX distinction is the entire difference. **The gate is green DESPITE
   printing the parse errors into the log**, because under `output: prefixed`
   gofmt's stderr lands on Task's stdout. Visible-and-ignored is worse than
   silent: the error text reads as the gate having done its job.

**The comment is mandatory.** Both reasons, the measurement, and an explicit "do
not simplify this line" — otherwise the next editor rewrites it as `test -z` for
clarity and silently restores the hole.

Also forbidden, and worth naming so nobody adds them: no `{{.CLI_ARGS}}` (the
splicing rule, and it lets a caller narrow the gate's scope); no `xargs`/`gofmt
-d $out` "improvement" that unquotes the filename list.

### R2 — Taskfile targets

`fmt-check:api` and `fmt-check:controller`, each with `dir:` set the way the
existing `vet:*`/`build:*` targets do, inserted **first** in `gate:api` and
`gate:controller` respectively (0.06s, so a coder learns about a misformat before
paying the 43-66s `-race` compile).

Plus a composite `fmt-check` that **composes the two per-module targets**:

```yaml
  fmt-check:
    desc: gofmt -l over both Go modules
    cmds:
      - task: fmt-check:api
      - task: fmt-check:controller
```

**Never a root-scoped `gofmt -l .`.** Verified by the lead: a repo-root
`gofmt -l .` descends into dot-directories. `.go_job` sets
`GOPATH: "$CI_PROJECT_DIR/.go"` and `GOCACHE: "$CI_PROJECT_DIR/.gocache"` and runs
`go mod download` before any script line, so in CI a root-scoped walk would
traverse the populated module cache and red the gate on third-party source.
Neither directory is in `.gitignore`, so nothing else would catch it.

**Every target needs a `desc:`.** `task --list` shows only targets that carry one
(`--list-all` shows both), and four documents name `task --list` as the discovery
mechanism. A `desc:`-less target is invisible to all of them.

**The name is `fmt-check`, never `fmt`.** `.claude/agents/tester.md` instructs
testers to refuse fixing variants by name, `gofmt -w` among them — a `fmt` target
would be declined by the role that is supposed to run it. Say so in the comment
so nobody "tidies" it later.

Obey the Taskfile header's four bans verbatim. **Ban 1 is the live one here** and
was reproduced by the auditor: a `sources:`-carrying `fmt-check` printed
`up to date`, exit 0, and executed nothing. One argument the header does not make
and that is specific to this target: **a `**/*.go` fingerprint cannot see the
gofmt BINARY change**, so a fingerprinted `fmt-check` serves a stale green across
exactly the toolchain bump most likely to introduce new drift. Put that in the
comment, because a `sources:` glob is *more* defensible here than elsewhere
(gofmt reads nothing across the module boundary) and is still wrong.

**Named anti-pattern, created by R1's own wording**: do not implement
"print and fail" as `vars: {DRIFT: {sh: gofmt -l api}}` + `test -z "{{.DRIFT}}"`.
That is a banned dynamic root var *and* it splices shell output into a
`text/template` result that reaches `sh -c`.

### R3 — CI: extend `validate:api` and `validate:controller`

**Settled. Do not open a new job.** `task fmt-check:api` goes **first** in
`validate:api`'s script, `task fmt-check:controller` first in
`validate:controller`'s.

The decisive argument is anchor wiring, not runtime. `.gate_needs` and
`.publish_needs` enumerate jobs **by name** (verified by the lead — both lists
carry `validate:api` and `validate:controller` already). A new `lint`-stage job
is in neither, so forgetting to add it to both produces this repo's signature
failure shape: a red job that nothing `needs:`, with the images and chart
publishing anyway.

Secondary arguments, all pointing the same way: zero new `.task_setup` fetches,
zero new `cache:` cycles, no `go mod download` paid for a check needing no
modules, no new `rules:` block to get wrong (a new job omitting
`rules: - if: '$UZI_CI_DEMO_FAIL != "1"'` would run on and pollute the Fix-CI
demo pipeline), and `format` and `lint` are separate slots in both slot tables —
putting a format check in the `lint` stage conflates them and pre-empts M3.

Placement is **first**, not appended: appended, it would run only when the sqlc
gate already passed, and would inspect a tree `sqlc generate` has just rewritten
— the PRD's own "latent deadlock" note. First keeps the two checks reading
disjoint tree states.

Stated as a negative so nobody copies the wrong precedent: **do not add
`- if: '$CI_COMMIT_REF_PROTECTED == "true"'`.** That is `e2e:kind-smoke`'s shape
and would make the format gate post-merge only.

### R5 — the liveness control (Success Criterion 8)

Introduce a deliberate misformat in a scratch file under `api/`, run
`task fmt-check:api`, confirm it **reddens and names that file**; restore and
confirm green. Repeat for `controller`. Record both in the MR description.

Three constraints that make it an actual control:

- **Quote the exact filename the gate printed.** `CLAUDE.md`: *a control that
  produces no output is not a control.* A green run naming nothing proves nothing.
- **The printed path is module-relative** (`internal/…`), not repo-root-relative,
  because the target carries `dir:`. Record what it actually printed.
- **Verify the restore with `git status` / `git diff`, never by re-running
  `gofmt -l` and reading an empty list** — an empty list is equally consistent
  with having deleted the wrong thing.

`task` exits **201** on any failure, never the underlying code. Test `!= 0`,
never `== 1`.
