Claude usage limits, per user

Anthropic enforces two account-wide windows — 5-hour and 7-day — but nothing in uzi shows them today, so a run can hit a wall mid-flight. A background poller reads each user's own utilization every 5 minutes with their stored token; every user sees their own two meters, admins see the whole factory. Tones follow uzi's worker-gauge thresholds: ok under 80%, 80%+, 95%+.

How the numbers get there

1 · poll

A backend engine (modeled on the self-improve poller) ticks every UZI_USAGE_POLL_INTERVAL (default 5m). It lists users holding an anthropic_token secret and skips anyone whose vault is locked — their last reading stays, marked stale.

2 · probe

Per user it tries the free /api/oauth/usage endpoint first; if that credential is refused (429 for setup-tokens), it sends a minimal Haiku request (max_tokens: 1) and reads the anthropic-ratelimit-unified-* response headers. Worst case ≈ 1 token per user per 5 min.

3 · store & serve

One row per user (5h%, 7d%, resets, synced_at). GET /api/me/rate-limits returns your own; GET /api/admin/rate-limits returns everyone's, admin-gated. The SPA re-reads on its normal 10s visible-poll.
