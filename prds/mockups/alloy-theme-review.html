What Ember already gets right

The current theme has a coherent molten-metal identity, semantic color tokens, distinct status colors, shared focus styling, and reduced-motion support. Grouped navigation, board attention strips, search and filtering, and current-activity lines already exist. Keep those foundations.

Source review: web/src/index.css, web/src/components/AppShell.tsx, web/src/pages/Dashboard.tsx, and web/src/pages/Board.tsx.

Current Ember reference

Actual Ember admin demo captured from the current app, 1440 × 960. This is the existing layout with sample data; the top-bar Ember switch only previews its palette on Alloy’s proposed layout.

Theme changes

Lift the canvas from Ember’s #080A0F to graphite #171B20. Use a more neutral surface ramp and a warm nickel accent in place of orange. Give readable task titles more weight, use Avenir Next with local system fallbacks, and reserve monospace for technical content. The palette switch previews color only: both settings use this proposed layout and typography.

Experience changes

  1. Put decisions before inventory. Today the overview leads with four similarly weighted metrics, then worker load and usage before recent work. In the reviewed admin demo at 1429 × 962, Recent runs began below the first screen. This proposal elevates pending approvals, keeps active work in the centre, and moves operational context aside.
  2. Make cards easier to scan. Keep the existing current-activity information, but separate the task title, run state, current step and spend. Group less frequent display controls in one menu; offer Board and List views over the same items. Repeated orange Start run buttons currently compete with review decisions; here each card opens its context, and the primary action belongs to the decision surface.
  3. Keep approval close to the plan. The current run view already offers a summary, plan, milestones, crew selection and By agent / Timeline activity. This proposal reorders those concepts around a plain-language summary and concrete steps, with technical details on demand. Production work must preserve activity views, crew selection, rejection, and non-approval attention states such as agent questions, follow-ups, failures and resource waits. These controls and states are outside this sample; the proposal does not remove them.
  4. Offer a comfortable default. Consistent 14px body text, restrained status color, fewer nested containers, and a compact density option for busy boards. Mobile keeps horizontal scrolling inside the board.

Try the proposal

Open a plan from Overview, request a change or approve it, and return to the board to see its state move. Search for “worker,” filter by status, switch to List, or use Display to hide costs and current steps. Use the top bar to compare palettes.

Everything is sample data. Actions only change this browser page’s memory; refreshing resets it. Counts and today’s spend derive from the same sample items. The seven-day chart is an illustrative series, not live telemetry. Disabled navigation marks screens outside this prototype. A production implementation would require component work, semantic token mapping, full contrast checks, and responsive and keyboard verification.
