What changes, and who proposed it

both UX agent and Codex buddy agree your call moves or changes existing UI
  1. 1

    One progress card holds the percentage, the track, the milestone list and the live work

    bothyour call

    The separate “Milestones (reported complete)” card goes away. The current milestone expands to show every live agent lane (two on m9 today), replacing the single “Active role” line. Done rows are muted, pending rows faint.

  2. 2

    “Now” sits under the active milestone, and says what the work is

    UX agentchecked in code

    The api shows a Now note only for exactly the active milestone it was written for, so placing it under m9 claims nothing the server did not. Today the note often restates the tool (“Running a bash command”); a worker prompt change makes it describe the work from the milestone title and the agent’s label, which the mock shows.

  3. 3

    One milestone vocabulary: “3 of 4 reported complete”

    both

    Drops “M3/4” from the header while the card renders, and “milestone 4 of 4” from the card head. Keeps the honest wording “reported complete”; a run whose worker reported nothing reads “– of 4 reported”, never “0 of 4”.

  4. 4

    Phase stepper becomes one chip: “phase: implement · iteration 4”

    both

    The three-step strip implies earlier phases passed, which the code does not know, and needs a caption to explain itself.

  5. 5

    Header keeps state and identity only; settings go behind “Run settings ▾”

    bothyour call

    Header: status, elapsed/budget (a parked run shows “clock stopped”), harness and model, one token chip. Switch token, token history (shown only with two or more entries) and the two run toggles move into the disclosure. A credential problem still surfaces as an attention panel.

  6. 6

    Pause and Stop move up to the header

    bothyour call

    Same buttons, same confirmation and ownership gates. The Steer composer and its queue stay at the bottom.

  7. 7

    Whatever needs you comes first

    bothyour call

    Plan approval, questions, holds and the completed/failed outcome render directly under the header, above progress. Today the plan panel sits below the run summary, archives and judge, and the outcome heroes below the run summary. Switch the state above to see each.

  8. 8

    Cost as one footer line; run summary collapsed after the gate

    bothyour call

    “$32.56 · 58.9M in (93% cached) · 334k out” with the unrecorded tail kept separate, linking to the full tables. Unavailable cost shows as unavailable, never $0. The summary stays expanded while awaiting approval and remembers your per-run choice.

Kept as-is in any build: untrusted milestone, lane and Now text rendered as sanitized plain text; intent and plan through the hardened Markdown renderer; the polite live-announcement region; no new pulsing element (a lane pulses only with a live frame); keyboard disclosures with aria-expanded; reduced-motion respected.
Also found: the header spinner ignores reduced-motion; the card and the checklist read “in progress” from two different fields. The merged card keeps each field’s meaning: row marks from the reported in-progress list, the Now note and track from the active milestone the server names.
