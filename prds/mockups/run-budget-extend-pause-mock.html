See the clock, extend it, pause the run

One run (issue #1183, six milestones, 8h frozen budget) at three moments: healthy, near its timeout, and paused by its owner. The clock is the active time the timeout sweep kills on: wall time minus every park. The server computes the deadline once; web, TUI and CLI read it.

A healthy run changes almost nothing. The web folds the budget into the elapsed text it already shows; the TUI is byte-identical. The header grows a control only when the state calls for one, the way Expedite appears only on a queued run: Extend when near timeout, Resume when paused. Pause lives with Stop run in the owner actions. A pending pause is a flag on the run, like stop, never a status of its own.

Revised 2026-09-07 after a UX review: no pausing state, a retractable pause request, Extend always opens a chooser, plainer paused copy.

1 · ask

Pause ▾, in the owner actions

The owner picks how. The default finishes the milestone in flight, because that is where work is committed and a checkpoint already publishes.

After current milestone recommendedFinishes M4, pushes a checkpoint, then parks. Nothing in flight is lost.
Pause nowDrops the turn in flight. Work since the last checkpoint (9m ago) is discarded.
Paused time does not count toward the 8h budget. On the final milestone only Pause now is offered.
2 · winding down

Pause requested

Not a status. A sticky flag on the run, like stop: the lead starts no further milestone and the harness parks at the boundary. Until then you can withdraw it or escalate.
