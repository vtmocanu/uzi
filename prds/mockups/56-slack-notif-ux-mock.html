Slack notifications: tell the user why the DM can't send

Today the Settings → Notifications card looks identical whether Slack is fully working or was never configured by the admin. On dev-cluster Slack isn't set up at all, so auto-match never runs, the status sits at "Not linked" forever, and "Send test DM" is silently disabled with no explanation.

Proposal: expose the workspace connection state in GET /me/slack (one non-secret string) and let the card explain itself in each state. Dashed outlines mark what's new.

What it takes

  1. API: add workspace to the GET /me/slack DTO — the manager's existing state (disabled / connecting / connected / error:*) collapsed to unconfigured | connecting | connected | error. Non-secret, read from h.slackState(), same source the admin chip already polls.
  2. Web: in SlackNotifications.tsx, render the state-A info alert and disable the controls when workspace !== "connected"; add the one-line hint under the disabled "Send test DM" button (state B); add the pending-state helper line (state C).

No schema or behavior changes on the notification path itself; the button was already correctly disabled — it just never said why.
