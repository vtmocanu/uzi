Design notes

  1. One card per work run, not one row per checker. A card holds every plan round and the code check for that run, so round 5 failing after four rounds of changes is read as a sequence. The card sits in Active while any attempt is queued or running, otherwise in Past.
  2. Three questions, three columns. Check says whether the checker ran to the end. Verdict says what it concluded. Effect on the run says what uzi did next. The work run's own status stays in the card header, labelled "Work run", so a check that did not finish never makes finished work look failed.
  3. "Didn't finish" is not a verdict. Changes requested and Blocked are finished checks with a result. Didn't finish, Couldn't start and Replaced are execution outcomes; Replaced is greyed and kept out of failure counts.
  4. Honest gaps. An attempt with no checker run says so and disables Open checker. When the cause was not recorded, the row says "Cause not recorded" instead of guessing.
  5. Selector appears only with evidence. Runs | Cross-checks shows when the viewer has any active or retained attempt, including attempts that never got a checker run, and stays after the setting is turned off. Without evidence the page is today's Runs page.
