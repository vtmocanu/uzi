# PRD #862: SAST enforcement in the gate — gosec + semgrep invariants

**Issue**: #862
**Priority**: Medium
**Status**: Draft

## Problem

uzi's code is authored by AI agents at volume. Security properties held only by
convention (CLAUDE.md prose) plus reviewer vigilance get regressed silently,
because the "author" has no memory of the rule and ships more code per human
review-pass than a person would. Today nothing security-shaped runs in
`task gate` locally or blocks a PR:

- `golangci-lint` gate enables `errcheck, staticcheck, ineffassign, unused, unparam, nolintlint` — **no security linter** (no gosec).
- The only SAST is **CodeQL** (GitHub default setup): interprocedural taint, Go + JS, but **GitHub-only, async, advisory** — it blocks nothing and lands findings after the fact.
- `gitleaks` (secrets), `govulncheck` (dep CVEs, not in gate), `actionlint`/`zizmor` (CI) exist. No semgrep.
- **None of uzi's own product invariants are mechanically enforced** — no secret-reveal endpoint, worker routes cookie-free, `settingSources: []` never widened, forge driver only via the interface. These are the product thesis and they rest on convention + tests.

## Solution

Shift from "review catches it" to "the gate enforces it" for an agent-authored
repo, adding in-loop, blocking checks that fill a coverage axis CodeQL does not
(fast / local / blocking, and project-specific). Two mechanisms, chosen per
invariant by what can actually express it:

1. **gosec** — enable inside the existing `golangci-lint` gate (it ships as a golangci v2 linter). Generic Go security smells, every push, ratcheted.
2. **golangci `depguard`** — enforce the import-boundary invariant (forge driver only via interface) natively in-toolchain, riding the same ratchet. No new tool.
3. **semgrep** — encode the remaining uzi guardrail invariants that are **syntactic / path-scoped** (no cross-function taint) as deterministic rules.

**CodeQL stays as-is** and remains the owner of the **interprocedural-taint**
invariants (PAT→log-except-redactor, raw-client-bypasses-allowlist) — semgrep OSS
is intraprocedural and would be high-false-negative on those, so this PRD does
**not** try to encode them in semgrep. A second general SAST (Snyk/Sonar) is out
of scope (pure overlap with CodeQL).

## Scope notes (read first)

**Workflow-scope guardrail.** The uzi worker PAT lacks `workflow` scope, so **any
`.github/workflows/**` edit in the branch diff is an atomic push rejection that
loses the whole branch** (`.claude/rules/prds.md`). **M5 (wire the semgrep job
into `ci.yml`) is maintainer/local-only and MUST NOT appear in the worker's
branch.** M1-M4 and M6 touch `.golangci.yml`, a new `semgrep/` dir,
`scripts/`, `Taskfile.yml`, `docs/`, `.claude/rules/` — no workflow files.

**semgrep acquisition — resolved: BYO on PATH, delivered to workers via the baked
toolchain.** Unlike gitleaks/golangci (single static Go binary, curl+sha256), semgrep
is a Python/OCaml tool with no static binary. Rather than invent a pinned-download
mechanism, semgrep follows the repo's existing pattern for non-Go gate tools
(`scripts/lint-yaml.sh` yamllint, shellcheck): **bring-your-own on PATH,
`command -v` + install hint**. `scripts/semgrep-gate.sh` mirrors `lint-yaml.sh`'s
shape. Each consumer supplies semgrep its own way: devs install locally, CI installs
it (M5), and **the uzi worker gets it from its baked toolchain** —
`agent/devbox-global/devbox.json` already ships `yamllint` and `shellcheck.bin` the
same way (semgrep is nixpkgs `semgrep`).

**🔴 This makes M0 a hard prerequisite for the semgrep milestones on a uzi run.** The
baked toolchain is realized into the worker image at *build* time, so semgrep reaches
the fleet **only after a release + worker roll** (M0). Until the fleet has rolled, a
worker's `command -v semgrep` fails and it cannot run or validate M2-M4. gosec and
depguard (M1) are unaffected — they live inside golangci, already fetched — so **M1
can go to uzi immediately; M2-M4 must wait for the M0 roll.**

Every invariant in this PRD is derived from reading this repo (CLAUDE.md,
ARCHITECTURE.md, named source files) — no open-web lookup is needed to author them.

## Milestones

### M0 — ship semgrep in the baked worker toolchain (🔴 MAINTAINER / LOCAL — release + fleet roll)
Prerequisite for M2-M4 reaching a uzi worker. Not implemented by the worker.
- [ ] Add `semgrep` to `agent/devbox-global/devbox.json` `packages` (alongside `yamllint`/`shellcheck.bin`) and regenerate `devbox.lock` in lockstep — the lock is a flake-ref pin generated by a real arm64 devbox build, so bump both together (per that file's note).
- [ ] Confirm semgrep substitutes **prebuilt** from `cache.nixos.org` on x86_64-linux at the pinned rev (its OCaml `semgrep-core` closure is chunky — same concern the file flags for `chromium`), so the amd64 kaniko image build does not compile it from source. Tester validates `command -v semgrep` on the built image's agent PATH.
- [ ] Land direct-to-main, **cut a release**; the worker image rebuilds and `scripts/worker-tag-autobump.sh` moves `workers.image.tag` so the fleet rolls (busy workers drain up to 24h, idle roll now).

**Success criterion**: `uzi worker list` shows the fleet on the new tag and a worker's `command -v semgrep` succeeds. Only then can M2-M4 be sent to uzi.

### M1 — gosec + depguard in the golangci gate (uzi-swippable, no M0 dependency)
- [ ] Add `gosec` to `linters.enable` in `.golangci.yml`. It rides the existing ratchet automatically (the `issues:` block: `new-from-merge-base: origin/main` + `whole-files: true`). Enabling the linter changes only `.golangci.yml`, so **no `.go` file changes in the enabling MR ⇒ no gosec finding blocks it**.
- [ ] Add `depguard` to enforce invariant #7 (arch boundary): no package outside `api/internal/forge` imports `gitlab`/`forgejo`/`github` drivers directly. Native golangci, rides the ratchet. Cheaper and in-toolchain vs semgrep.
- [ ] Record the pre-existing gosec backlog for visibility in the MR description via `task lint:api:all` / `lint:controller:all` (these already hard-code `--max-issues-per-linter=0 --max-same-issues=0` — no extra flags needed). Do **not** burn the backlog down here (scope creep); the ratchet holds the line.
- [ ] If gosec's default ruleset is too noisy on a known-safe idiom, tune via `linters.settings.gosec` with a one-line justification (per this file's "every disabled linter owes a justification" convention). Note the tree already carries several inline `//nolint:gosec` directives (G115 int-overflow, G401 sha1) — enabling gosec makes those currently-vacuous suppressions real, so the backlog is real but bounded.
- [ ] `task gate:api` and `task gate:controller` green.

**Success criterion**: a newly-introduced gosec finding (e.g. `math/rand` for a token) reddens `task lint:api` on a branch; the pre-existing backlog does not block an unrelated MR. A new direct driver import reddens the gate via depguard. Calibrate with a real exported-symbol probe (mirror CLAUDE.md's lint-calibration discipline).

### M2 — semgrep harness wired into the gate (uzi-swippable; requires the M0 roll on a worker)
- [ ] Write `scripts/semgrep-gate.sh` as a BYO-on-PATH wrapper mirroring `scripts/lint-yaml.sh` (`command -v semgrep` + install hint on miss). Acquisition is resolved (M0 / Scope notes) — no pinned-download mechanism to build.
- [ ] 🔴 **The wrapper MUST point semgrep at a writable settings path + disable metrics.** Verified on a live 0.71.0 worker (2026-08-30): the baked binary resolves (`/opt/uzi-toolchain/bin/semgrep` → nixstore `python3.14-semgrep-1.164.0`) and prints `1.164.0`, but on first run it writes `$HOME/.semgrep/settings.yml`, which **aborts** if that path isn't writable (an ad-hoc `exec` hit `Permission denied`; a writable `HOME` fixed it). So export `SEMGREP_SETTINGS_FILE=<writable, e.g. a mktemp/repo-tmp path>` and pass `--metrics=off --disable-version-check` in the wrapper, so the gate never depends on `$HOME/.semgrep` being writable in the run env.
- [ ] Add a `sast:semgrep` Task target and wire it into `task gate` (via `gate:repo` or a new `gate:sast`) so it blocks locally.
- [ ] Ship **one trivial proof rule** with a positive control (a canary that fires) proving the harness runs, using the repo's canary convention (`scripts/*-canary.*`, e.g. `scripts/gitleaks-canary.txt`) — not a new `probes/` dir.

**Success criterion**: `task gate` invokes semgrep; the canary proves the scanner actually ran (guards against a vacuous 0-findings pass).

### M3 — semgrep rules for uzi's syntactic guardrail invariants (uzi-swippable)
Author a calibrated set (target 3-4) of the **AST / path-scoped** invariants — the ones semgrep OSS can express without cross-function taint. Each rule ships a positive control (fires on a violation) and a negative (does not over-fire on the clean tree).
- [ ] **#2** no reveal endpoint for secretbox-sealed values — no handler returns a decrypted PAT/Anthropic token (`api/internal/secretbox`).
- [ ] **#3** `/api/worker/*` handlers never read a session cookie / CSRF — they authenticate Bearer-only via `RequireWorker` (`api/internal/middleware/worker_auth.go`, **not** `auth.go`, which is the cookie/CSRF path).
- [ ] **#6** `settingSources: []` is never widened (agent SDK config; asserted in `agent/src/sdk-executor` / `judge-runner`).
- [ ] (#7 is handled by depguard in M1, not semgrep.)

**Deferred to CodeQL (do NOT encode in semgrep):**
- #1 PAT/sealed value never reaches a log sink except through the redactor (`api/internal/forge/redact.go`) — interprocedural taint.
- #4 outbound forge base URLs stay allowlisted / no raw client bypasses `FORGE_ALLOWED_BASE_URLS` — interprocedural taint.
- #5 guardrail deny-hook covers *every* push/force/rewrite shape (`agent/src/guardrails.ts`) — a completeness property semgrep cannot prove (it matches presence/absence of specific shapes only).

**Success criterion**: introducing a violation of a shipped rule (a new `/api/worker/*` cookie read, a `settingSources` widening, a new sealed-value reveal path) reddens `task gate`; the clean tree passes.

### M4 — docs (uzi-swippable, own milestone)
- [ ] Document the security gate: what gosec/depguard/semgrep enforce, how to add a semgrep invariant rule, and the ratchet/backlog behaviour, following existing `docs/` patterns.
- [ ] Note in the relevant `.claude/rules/*.md` that these guardrail invariants are now mechanically enforced (so the convention and the check agree).

### M5 — wire semgrep into CI (🔴 MAINTAINER / LOCAL ONLY — not in the uzi worker's diff)
- [ ] Add a `sast` job (or fold into an existing gate job) in `.github/workflows/ci.yml` invoking the same `task` target as M2, so CI and local cannot drift.
- [ ] Confirm the job is required on the PR gate.

**Done in-session by the maintainer after M1-M4 merge** — `ci.yml` is workflow-scope and cannot be in the worker's branch.

## Success criteria (overall)

1. A new Go security regression (gosec class) blocks the PR gate locally and in CI.
2. A new direct forge-driver import blocks the gate (depguard).
3. A violation of any shipped syntactic uzi invariant (worker-cookie, reveal endpoint, `settingSources` widening) blocks `task gate`.
4. Pre-existing backlog does not block unrelated MRs (ratchet works).
5. CodeQL untouched and still owns the interprocedural-taint invariants; no second general SAST added.
6. Local `task gate` and CI enforce the same rules (no drift).

## Risks & mitigations

- **semgrep reaching the worker** → resolved via M0 (baked toolchain + release + roll); M2-M4 must wait for the roll, M1 need not. Confirm the closure substitutes prebuilt (M0) so the image build doesn't compile semgrep-core.
- **gosec noise / false positives** → ratchet (only new findings gate) + justified `settings.gosec` exclusions; do not burn the backlog in M1.
- **semgrep false positives** → ship a small calibrated subset, each with positive+negative controls; expand rule-by-rule.
- **Over-claiming coverage** → syntactic rules are defense-in-depth beside CodeQL + tests; the taint invariants (#1/#4) and the completeness one (#5) stay with CodeQL/tests, not oversold as semgrep-enforced.
- **CI cache budget** → semgrep is fast, needs no large cache; do not add per-job caches (see closed #673 — repo cache already over 10 GB).

## Dependencies

- Existing golangci ratchet (`.golangci.yml` `issues:` block) — M1 relies on it.
- Existing pinned-tool-via-`task` pattern (gitleaks/golangci wrappers) for gosec; the BYO-unpinned pattern (zizmor/yamllint) as the fallback shape for semgrep.
- **External: semgrep** — a new non-Go dependency, delivered BYO-on-PATH: baked into the worker toolchain (M0, nixpkgs `semgrep`), installed by devs locally and by CI (M5).

## Out of scope

- A second general-purpose SAST engine (Snyk Code, SonarQube, another taint engine) — overlaps CodeQL, adds noise/cost, no unique coverage.
- Encoding interprocedural-taint invariants (#1, #4) or the deny-hook completeness property (#5) in semgrep — CodeQL/tests own these.
- Changing CodeQL's setup or cache footprint (separate, low-ROI; see #673 close).
- Container image scanning (trivy) — possible future, not this PRD.
