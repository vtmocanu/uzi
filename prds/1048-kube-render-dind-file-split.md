## Solution

Pure motion, same package. **No exported-API change, no behaviour change, no rendered-object change (the spec hash of every worker is byte-identical), no test-code edit of any kind.** The three seam blocks move verbatim into `render_dind.go`; the only new text is the file's package clause, imports, and a two-line header comment placed **below** the package clause after a blank line (the #963 rule, so `go doc -all` never sees it as a package doc comment). Imports are whatever the moved code needs (`corev1`, `metav1`, `resource`, `protocol`, `fmt`; `goimports` decides).

## Decision Log

- **D1: DinD-only, one new file, no finer cut.** The epic's researchers measured this seam as clean and self-contained (no caller outside `podTemplate`/`RenderPVCs`, `render_test.go:620-1600` already groups its dind tests) and left `render.go` "just under the bar" at ≈957-968. A `render_dind.go` of ≈400 lines is one theme (PRD #83 M3 + #89 + #224 M-a's sidecar), and a further split of it (consts vs constructors) would put the wiring consts one file away from the only code that reads them. One file, three commits.
- **D2: the naming seam stays in `render.go`.** `render_naming.go` (the five `*Name` one-liners + `objectLabels` + `IsOurs`, ≈79 lines) would move the symbols the open PRD #837 (`Planned` + `uzi`, sweep paused) and ADR-0091 cite as "in render.go"; those are prose anchors, not diff conflicts, but repointing an ADR and an unlanded PRD for 79 lines is the wrong trade during the freeze. Recorded here so it is not re-found.
- **D3: `dindDataPVCName`, `dindDataSuffix` and the two container-name consts stay.** They live in mixed blocks beside their non-dind siblings (`deploymentName`…`nixPVCName`; `tokenSuffix`/`dataSuffix`/`nixSuffix`; `workerContainerName`/`seedContainerName`), `materializer.go` calls `dindDataPVCName` at three sites, and splitting a const block to move two lines is the kind of "motion" that reads as design. The rule: a mixed block stays whole; a block that is entirely dind moves whole.
- **D4: zero test edits, including comments, and this is the one rule that must survive an implementer's tidiness.** `render_test.go` carries all 24 of the package's findings; `whole-files: true` gates the whole file the moment it appears in the diff. `render_test.go:731`'s "render.go builds the docker init containers … as slices" stays true anyway (the slice-building is `podTemplate`'s), so there is nothing to repoint. If a test **must** change (it must not: SC1), stop and report rather than accept a red `lint:controller`.
- **D5: `go doc -all` (no `-u`) is the byte-identity instrument**, as in #921/#963/#1008, and here it is trivially satisfied because nothing exported moves; the load-bearing proof is therefore SC1 + SC3 + SC6 (the hash-pinned render tests over an unmodified test file), not SC2. Both are still required.
- **D6: the chart's mirror comment is repointed, the mirror itself is untouched.** `worker-invariants.yaml:241` ties the Helm literal to the Go const by comment in both directions; the Go side (`:265-271`) moves with the const and already names the chart file, so only the chart side needs the new filename. The tie is also mechanical (`TestDinDDataDefaultFitsTheChartsLimitRangeMax`), which is unaffected.

## Risks & mitigations

- **A moved constructor references a `render.go` const the table left behind (e.g. `workerContainerName`, `dataMountPath`, `dindDataPVCName`).** Same package, so it compiles regardless; that is the intended shape (D3). No cohesion fix needed.
- **A positional comment inside a moved block goes stale.** Neither `--color-moved` nor the tests see it; sweep each block for `above|below|this file|:\d{3,}` and fix in the same commit, listed in the PR. The three known candidates are checked in M1 and expected to stay true.
- **`goimports` drops an import `render.go` no longer needs or the new file lacks one.** The compiler and `task fmt-check:controller` catch both; do not hand-edit import blocks beyond what the compiler asks for. Measured at `d6f39a0`: `render.go` still uses every one of its current imports after the cut (`appsv1`, `corev1`, `metav1`, `resource`, `protocol`, `preset`, `strconv`, `fmt`, `sha256`/`hex`/`json`), so its import block should be untouched and its diff purely removed blocks; `render_dind.go` needs `corev1`, `metav1`, `resource`, `protocol`, `fmt`. If `goimports` wants anything else, that is a signal to re-check the cut.
- **The YAML comment edit in `worker-invariants.yaml` changes the rendered chart.** It cannot (a `#` line inside a template is stripped); `task lint:yaml` (part of `gate:repo`) runs over the file, the CI `helm template` steps re-render the chart on the PR, and M2 adds a local `sha256sum` before/after where `helm` happens to be on PATH.
- **`specs/ai.md` numbering collision** with #1022, #1034, #1042 and #1049 landing the same night: re-derive at landing (M2).
- **In-flight overlap: none on the files this PRD edits.** Checked 2026-09-02 at `d6f39a0`: #1022 is `api/internal/handler/**`; #1034 is `api/internal/{forge,forgesvc,store}` + `handler/board.go` + four `web/src` files; #1042 is `api/internal/workersvc/**` + `agent/src/git.ts`; #1049 is `web/src/pages/Judge.tsx` + `web/src/pages/judge/`.
