## Design

**One vocabulary.** The open state is "To triage" everywhere: the tab (already), `ROLLUP_LABEL.todo`, `BRIDGE_ADJECTIVE.todo` ("to triage"), the `TriageSummary` legend ("to triage"), `DispositionChip`, `OccurrenceBucketChip`, and Findings' tab and chip (was "To file"). Filed is a link chip "Filed #N ↗" in the state slot on every surface (the green "Issue created." and "Filed." boxes go; a created-with-warning line stays under the chip). Dismissed carries its reason where the DTO has one: "Dismissed · Won't do" / "Dismissed · Not an issue" (the run page already does; Findings gains `dismiss_reason` on the wire), plus the existing "Dismissed · barred CLI". Done keeps "✓ Done" / "✓ Done via #N". Counts: a Judge group reads "N open of M runs" (`openOfRunsLabel(open, runs)`; a fully settled group reads "M runs, all settled"); a Findings row prints "seen in N runs" only from 2 up. The dismiss reasons keep their two explanatory lines; the second reads "False positive, the judge got it wrong" on judge surfaces and "False positive, the worker got it wrong" on findings.

**One component set, `web/src/components/triage/`.** `TriageActions` (the row: File issue · Mark done · Dismiss ▾; props `{ onFile?: () => void; onMarkDone?: () => void; onDismiss?: (reason: "wont_do" | "not_an_issue") => void; dismissCopy?: "judge" | "finding"; busy?: boolean; announce?: string }`, an absent handler means that button is not rendered; all `Button size="sm" variant="secondary"`; the Dismiss menu with Escape, outside-click and `aria-haspopup="menu"`, lifted from `GroupDisposeControls`). It has **two mutation modes, decided by the caller**: (a) *owned*, the run page and the finding card, where the caller's handler does the optimistic call, the single-row refetch, sets `announce` for the sr-only live region and the successor-focus rule moves focus to Undo, all lifted from `DispositionControls`; (b) *delegated*, the Judge page's group row and both multi-select bars, where the handler only forwards to the page's bulk call and toast Undo, and no live region or successor focus applies (a settled group may leave the bucket on reload, so there is no successor to focus). `TriageDisposedRow` (the disposed state the run page shows today: `resolvedAgo(set_at)`, the server-computed `disp.stale` badge "recommendation changed since you resolved", and Undo; a different stale signal from the filed-link one, and it survives the swap). `TriageStateChip` (the ladder above, one place; it takes a **normalized** `state` prop, `"to_triage" | "filed" | "done" | "dismissed"`, plus `reason?`, `set_via?`, `filed?`, because the two wires key the open state differently, `todo` on the judge and `to_file` on findings (`workersvc/findings_backlog.go:24`): the wire keys stay as they are, and `triageCopy.ts` exports the normalized map plus one adapter per surface, `judgeState(occ | disp)` and `findingState(f)`). `IssueDraftCard` (the card: "Draft issue" header, "needs your review" badge, provenance box, repo `Select` with `draft.default_note` shown as the info box while no repo is picked, or a fixed read-only repo with no note, Title, Description, labels, the "Lands on the board…" hint, Create issue / Cancel, Retry on a failed draft load, `stripUnsafeChars` on the uzi-supplied seed only, an optional stale-link warning). `SelectAllCheckbox`, and `triageCopy.ts` (the strings and label maps, exported and consumed by both pages so knip stays green; `judgeBacklog.ts`'s private maps move here or re-export from here). The new components use surface tokens (`bg-raised`, `bg-surface`), never `bg-ink`, so PRD #1167's light themes need no per-site audit of them. `isHttpsUrl` is imported from `api.ts` everywhere; the three private copies go (`GroupRow.tsx:308`, `OccurrenceFileIssue.tsx:12`, and `Findings.tsx:463`, where it is named `isHttps`). `OccurrenceFileIssue.tsx` and `RecommendationFiler` are deleted; `FindingCard`'s editor is deleted.

## Success criteria
