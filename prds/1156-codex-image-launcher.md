## Boundary and preserved behavior

M3a owns one reusable **supervisor-root launch primitive**, its isolated Codex process construction and installed image artifacts. The deliverable must be exercised through a packaged internal executable/entrypoint and the same implementation the later worker adapter can call, not a test-only copy or unused placeholder. Keep the normal worker entrypoint and Claude selection/execution unchanged; no real Codex run can be created or claimed because of this child. The public `api/cmd/uzi/` CLI needs no matching command: this is an internal worker primitive, not a user-facing capability.

The **per-run registry of all roots, immutable run/epoch launch reservations, callback admission/settlement, child-thread quiescence and outer `Executor.safety.withBoundary` permit remain later M3 integration**, implemented together with the real adapter and command handlers. M3a's primitive must be usable for both provider roots and independent command roots; a command requested through a callback is not an app-server descendant. Report cleanup for exactly the owned root. Never return a run-level `observed_empty`, mint a permit, or treat one drained root, app-server exit or a process-group kill as proof that the whole run is safe. Later integration must register every root before admission and aggregate same-epoch evidence exactly as the accepted contract requires; nothing here relaxes that requirement.

No credentials, refresh API, credential-default/identity design, full `CodexRunHarness`/advice adapter, worker callbacks, role/skill rendering, broad routing, model picker, pricing, image publication, rollout, release, API/web/schema change or migration. Keep the existing Claude source behavior and `agent/test/` assertions unchanged. Preserve frozen M0 characterization files; derive production code from their measured mechanism without rewriting its historical evidence.
