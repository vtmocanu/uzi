# PRD #1786: Retain stopped-generation sources before clone cleanup

**Issues:** [#1786](https://github.com/vtmocanu/uzi/issues/1786), the clone-discard exits of [#1790](https://github.com/vtmocanu/uzi/issues/1790). Overview: [#2746](https://github.com/vtmocanu/uzi/issues/2746).
**Status:** Draft 2026-10-11, revised after peer and architect review. Maintainer approved the preservation direction and the split (this PRD closes #1786; #1790's park-durability part moves to a later PRD after #1733) on 2026-10-11.
**Execution:** One gated run and one PR, an operator-channel prefactor followed by two serial vertical slices. No unfinished PRD is a prerequisite. No implementation or validation changes any file under `.github/workflows/**`.
**Evidence baseline:** `origin/main` at `cc4ed18c68f4e708e214c1da93834a74b81f02dc` (includes #2745). Anchors are symbols, not line numbers. All implementation investigation is repository-local; no open-web lookup is required.

## Problem

A worker must stop acting when its claim is fenced or superseded. That does not prove that unfetched commits, dirty tracked files or untracked work in its old clone survived elsewhere. Some quiet-stop paths still clear preservation flags and reach ordinary clone cleanup. A local restore point and a server terminal status are also insufficient evidence to delete the original source.

This PRD reverses the deliberate old cleanup convention documented above `handleRecoveryExhausted`'s `captureForCredentialExit`: the stop arms discard without capture because the new claim has its own clone. A successor clone does not necessarily contain the predecessor's unfetched or uncommitted bytes.

M1's reproduction hypotheses, not yet newly executed on this baseline:

- A non-guarded stale exit can reach `retireRunnerClone(discard: true)` and delete its source unless independent physical-terminal protection blocks retirement.
- A guarded stale exit can retain/freeze already-transferred bare roots while missing dirty/untracked bytes still in the clone; that bare-only evidence must not permit clone disposal.
- Some paths are already protected. `retireRunnerClone` refuses recovery sources without verified disposition, and the #1766 stale-vault test now expects retention when independent proof blocks cleanup. Tests must identify the remaining actual seam without weakening these guards to manufacture a failure.

## Outcome

A stopped generation keeps its exact local source and existing worker-owned attribution until complete preservation or explicit disposition authorizes cleanup. This is one physical-source rule for generic fenced exits and the corresponding recovery-handler exits, not a new archive store or lifecycle policy.

Acceptance examples:

1. A generation has an unfetched commit, a modified tracked binary and an untracked file when it receives `stale_claim`. Its own processes and attributed containers are quiesced without network or credential reconciliation; it stops without another stale run mutation. Its exact clone and journal survive cleanup and a worker process restart on the same pod/volume; an isolated local export reconstructs those bytes. The successor's clone and tracking tip are unchanged. Stale HOME/provider credential retention is not introduced.
2. A vault-deferred run has only a verified local restore point after checkpoint publication failed. Its existing park still proceeds under ADR-1197, but clone cleanup cannot delete an unpreserved source. The feed states local-only durability and the existing hold is not released by the new retention helper. No extra pre-park retry, archive requirement or worker-slot wait is added.
3. `RunningAckTerminalError` occurs before this flight seeds any clone. `flight.worktreePath` is unset, so no source is invented and the flight stops normally. Conversely, a clean clone containing unfetched commits is work-bearing, not empty merely because its porcelain is clean.

A Docker-tier `/data/runner` lives on a per-pod `emptyDir`; keeping a clone does not make it survive pod replacement or volume loss. The durable bare/journal can outlive a pod while the clone it describes does not. Run-bound ephemeral workers can also lose their data PVC after supported terminal cleanup when no open hold protects it. Diagnostics and the runbook must distinguish same-pod process restart, pod replacement and worker/PVC teardown, and report missing source honestly rather than treating a descriptor as surviving bytes. This PRD does not promise that unregistered local metadata prevents hosted teardown.

## Out of scope

- Changing park timing, adding a prerequisite to `recovery_wait`, or altering ADR-1197's accepted cross-worker checkpoint limitation.
- Adding an archive attempt before a park, splitting upload from FINAL, or making an owner archive an automatic resume source. #1790 keeps this remaining scope for a separate PRD, coordinated after #1733. Its proposed rule is one bounded authorized join-token archive attempt without blocking the park; it is not implemented here.
- New artifact storage, upload routes, run statuses, server retention authority or stale-claim hold creation.
- New forge publication, shared tracking updates through a stopped claim, automatic partial PRs, provider conversation transfer or arbitrary HOME/cache backup.
- Changing #2506 thin-release policy, #2743 verification limits, #1733 provider accounting or #1857's wider process-proof design.
- Generic reader hardening (#2483/#2524), generic context pruning (#2414), or automatic reclamation of unverified sources.
- Hosted fault injection as a worker milestone. A linked acceptance issue owns live validation.

## Modules and seams

### 1. Runner: latch source preservation before a quiet stop

Add a small runner helper, provisionally `retainStoppedSource`, with immutable flight identity (run, generation, repository/branch, actual seeded path and attempt id) and an exit reason. Its result is `no_source`, `retained_local` or `unknown`; none grants custody release or successor authority.

`no_source` means `flight.worktreePath === undefined`. If a path was seeded but is now missing, replaced, unreadable or unattributable, the result is `unknown`, not `no_source`.

At the `StaleClaimError` and steering `claimFence()` catch arms, latch `flight.preserveRecoveryClone = true` whenever `flight.worktreePath` is set before the first await, so a thrown proof cannot expose the clone to deletion. That latch must NOT skip process cleanup: explicitly run `quiesceRun(flight, executor, { mode: "own", site: "stopped_source", forceProcessScan: true })` in the arm, bypassing only credential/network reconciliation, not process proof. Use the existing predecessor-capture scoping when this flight has not executed its own model. The own proof kills only attributed processes, reaps HOME-attributed children and tears down this attempt's attributed Docker resources; it must never signal a live successor. A blocked/throwing proof keeps the clone, returns unknown and reports the unresolved writers, never a verified snapshot. Tests include a live child and an attributed container at the stale exit. The existing finally only runs own-mode `terminal_retire` quiescence when the preservation flag is false, so these preserving arms must not rely on it.

Retain clone and journal only in stale arms. Do not newly set `preserveSession`; allow existing authenticated credential/HOME cleanup after the own process proof, without credential release/refresh or provider reconciliation through the stale claim. If safe HOME removal cannot be proven, report that existing cleanup refusal explicitly rather than making indefinite credential retention part of this feature. Verify/retain clone attribution locally and stop silently. `RunningAckTerminalError` uses the same source-aware rule rather than assuming every future caller is pre-clone; its no-clone case still runs the established executor/resource disposal.

No stale `/state` report, forge publish, credential reconciliation, archive request, finalize replay or successor `refs/uzi-runner/*` write is introduced. Worker registration/heartbeat behavior is unchanged; a stopped flight must not claim it is still executing.

Cleanup still consults its existing locked source/receipt guards. In particular, guarded FINAL over bare roots cannot override this physical-source protection unless its authenticated inventory positively covers this exact clone's dirty/untracked representation and unfetched head. A terminal status, a covering successor commit or a released predecessor hold alone is not that proof. Preserve existing owner-authorized discard semantics, but require attribution before physical disposal.

### 2. GitCache: keep the existing source and descriptor

The artifact is the existing clone, not a duplicate. Reuse `RecoveryJournalEntry.retainedSources: RecoverySource[]` for stopped source attribution; keep the existing active branch journal when it still names the stopped source. The adapter must not overwrite a newer active journal. Existing protected descriptors (`uzi-retained.<runId>.journal`) can preserve a detached retained journal only under their existing identity/consistency rules. A cross-generation successor is not permission to rewrite its journal or tracking.

For attempt-based clones, the existing attempt id and seeded path isolate generations. Retain an uncaptured attempt under the ledger's non-disposable posture (`live`, or the existing `reclaimed` disposition when its release-in-place contract applies). Never mark it `abandoned` merely because execution ended: abandoned attempts are cap-reclaimable. Do not add a new ledger state or overload `recovery.stage` with an unsupported value.

Admission refusal is scoped to the retained physical attempt, not its run. A same-run successor on an attempt-capable worker uses a fresh attempt path and can proceed without deleting or reusing the retained predecessor. For legacy canonical clones, preserve the existing journal and refuse that unsafe canonical reuse; do not silently broaden the refusal to all same-run work. If a successor replaced that canonical path, do not capture, rename, WIP-commit or delete the successor. Preserve an independently attributable old attempt if it exists; otherwise retain all available evidence and report unknown/missing source. No implementation can recreate bytes already removed.

The caller-facing adapter must:

- Validate worker-owned run/repo/branch/generation/attempt identity and the actual source path, using the existing ownership/journal/ledger checks. Untrusted clone config is not authority. Legacy generation-less evidence cannot mint generation-exact archive authority.
- Take the bare/adoption lock through journal comparison and retention registration; respect `executionTails` and same-worker adoption exclusion. Revalidate mutable identity after awaits. Do not nest locks or introduce a new lock order.
- Preserve unfetched Git objects and the exact working tree, including tracked/untracked bytes, modes and links. Quiet-stop retention does not need a WIP commit or fetch-back, so it cannot advance shared tracking. Reuse existing capture only under its existing authority and quiescence requirements.
- Keep protected descriptors and physical paths on unknown quiescence, persistence failure, ENOSPC, age or cap pressure. A surviving writer prevents a snapshot/export from being called verified but never authorizes deletion.
- Leave the existing retirement and retention sweeps fail closed. Released custody is not physical-source proof: specifically test successor-adopted predecessor release from `recovery.sql` against dirty predecessor bytes that were never transferred.

Bounds: retaining an existing clone allocates no clone-sized copy. Registration is one finite operation under the existing recovery deadline. Bound new source-list materialization to `MAX_OWED_CANDIDATES_PER_RUN` (64); overflow retains the original journal and source, never truncates an inventory. Any new descriptor parsing validates keys, bounded byte size and path/string lengths before use. No unbounded directory enumeration is introduced. At ENOSPC, retain the ownership journal established before model execution; a new metadata write is not a prerequisite for retaining the original directory.

Do not give unverified source retention a deletion TTL. Refuse reuse of the affected attempt when retention cannot be represented safely, while allowing a fresh successor attempt; actual worker-wide disk-pressure admission retains its existing independent scope. Do not evict retained sources to make room. The existing source can exceed archive limits; this PRD bounds added work, not bytes already produced. Unverified retention must have an explicit reclaim path, below, including when no server hold exists.

### 3. Recovery-handler exit matrix

Audit every flag-clear site in `handleRecoveryExhausted` on this baseline. The table enumerates all nine direct `preserveRecoveryClone = false` sites; also audit `keepUnlessCaptured` and the cancel-ACK assignment, which clear the flag indirectly. The helper prevents cleanup only; report outcomes, interruption precedence and retry timing stay unchanged.

| Site (symbol/control condition) | Current disposition | New physical-source rule |
|---|---|---|
| `confirmRunningForCredentialPark`, `case stop` | Clear flags, return false | Local-only stopped-source retention; no stale network writes. |
| Ownership probe returns another generation | Clear flags, return false | Same stopped-source rule; do not touch the successor. |
| Ownership probe 404, terminal-disk and not credential-deferred | Clear flags, return false | Missing authority is unknown; retain a seeded source. |
| Ownership loop sees terminal status | Clear flags, optional existing settle, return false | Preserve source unless existing complete physical-source disposition covers it; terminal status alone is insufficient. |
| Terminal-disk recheck sees another generation or terminal status | Clear flags, return false | Preserve exact source under the same fence/terminal rules. |
| Terminal-disk finds `terminalResolved` or pending outbox terminal | Clear flags, existing failure reporting | Keep reporting precedence; pending reporting authority cannot authorize source deletion. |
| Credential-deferred park ACK is `recovery_wait` | Clear clone flag after local verification, return true | Keep park and timing; retain unpreserved local source. Existing complete physical cleanup authority is still required. |
| Park ACK has a terminal status | Clear flags, return false | Same terminal-source rule, no new report. |
| Park-report catch receives `StaleClaimError` | Clear flags, return false | Local-only stopped-source rule. |

A normal confirmed park with existing complete physical preservation evidence keeps its current cleanup behavior. This PRD adds no archive requirement, durable-before-park gate or additional retry loop. A local-only park still has ADR-1197's cross-worker limitation; preserving its original clone is valuable source retention, not a promise that another worker can automatically resume it.

### 4. Discovery and honest operator wording

Existing recovery discovery must find the retained exact clone and descriptor after a same-pod worker process restart. Use `materializeBootInventory` only when its existing exact-open-hold and producer predicates apply. Do not bypass those predicates to make a stale record uploadable. Missing/unreadable metadata or a missing emptyDir source is unknown/unavailable, never empty work.

The existing hosted reaper skips open holds referencing `live_worker_id`; local metadata alone is not a server retention capability. The new helper never releases that existing hold and does not rely on a stale request creating another one. If a successor releases the predecessor hold, the local source still needs independent cleanup proof; the product must not promise the hold will keep the pod forever. Actual pod/volume loss and explicit owner discard retain their documented consequences.

Update `docs/run-recovery.md` and the retained-source operator procedure to distinguish local source, archive availability, checkpoint durability and custody. Run `task docs:sync` in the slice that changes those docs. The existing backup script is `.agents/skills/uzi-watcher/scripts/backup-runs.sh`; verify that it can locate the reused source representation, without adding a new backup subsystem.

### 5. Worker-local inspection and explicit operator reclamation

No existing `uzi run discard --hold` operation names a local source whose hold is absent or successor-released. There is also no operator-invocable worker drain verb or existing local operator command channel. Hosted Cordon is controller-owned and is not this operation's idle fence. Do not invent a server hold, overload owner hold discard, stop PID 1, or replace the pod to obtain an idle point: that can destroy the emptyDir source before inspection.

Add the smallest missing mechanism in M0: a worker-local request channel, served by the live Worker process, with `inspect` and `discard` operations only. A Unix socket at `<dataDir>/ops/retained-source.sock` in a worker-owned 0700 directory, mode 0600, is the chosen transport; no TCP listener or API endpoint. The client entry point is `agent/src/ops/retained-source.ts`. It has no filesystem-discard implementation of its own: it sends a bounded request, and the live Worker invokes the GitCache adapter under its idle fence. Exclude the handler from model tool exposure, reject socket symlinks/unsafe ownership, and on split-UID workers test that runner/command UIDs cannot connect. The accepted single-UID runtime still cannot claim DAC isolation from an arbitrary same-UID process; document that existing local-administration trust limitation, and never treat the request as server custody authority. On single-UID workers this includes the model's own shell tool; the channel adds no capability beyond that UID's existing write access to `/data/runner`, and is not a model boundary. Add the client path and socket path to the `agent/src/guardrails.ts` deny patterns as defense in depth; the uid split remains the only real isolation.

The exact image invocation is `/app/node_modules/.bin/tsx /app/src/ops/retained-source.ts inspect --run <uuid> --generation <n> --attempt <id>` (or `discard` with the exact descriptor confirmation required below), executed as the worker administrative UID through the existing container exec surface. Runtime availability is resolved: `tsx` is a production dependency in `agent/package.json`; base Dockerfile line 222 and JVM Dockerfile line 168 run `npm ci --omit=dev`, their WORKDIR is `/app`, and both images copy `agent/src` to `./src`. Do not add a dev dependency or global installation. Add a packaging test that this exact client starts in the production-dependencies-only environment.

`inspect` is read-only and defaults to one specified run/generation/attempt. It produces content-free worker-local health evidence: retained count, measured allocated bytes, sample time, attribution/quiescence state and counts of missing/unknown sources. A bounded aggregate view can include up to 64 descriptors. One five-second inspection budget covers enumeration and byte measurement; timeout, oversized metadata, unreadable paths or exhausted traversal produces unknown/partial evidence, never a total of zero. Do not print source contents, credentials or arbitrary remote text. Emit the same bounded count/bytes evidence in structured worker diagnostics after source retention; inspection runs outside the claim/cleanup critical path. Existing central `fleet.disk` continues to show real aggregate disk pressure; it has no retained-source count fields, and this PRD does not mislabel its existing metrics as retained bytes or add a telemetry migration.

`discard` requires explicit operator authorization of the exact run/generation/attempt plus the inspected descriptor identity. There is no bulk, glob, TTL or automatic discard. The runbook says to verify the worker/run identity, inspect/export when desired, and explicitly accept destroying possibly unique work. If an open server hold exists, use its owner disposition first; this command changes no server custody. For absent/released holds, the operator must confirm that exact local source directly, which is the reclaim path these cases otherwise lack.

The live handler, not the operator, establishes the idle point. Reuse `DindPruneGate` from `agent/src/dind-prune.ts`, adding a distinct `retained_ops` blocker so releasing it never opens a cache/maintenance blocker. Wire this same gate into Worker unconditionally, even when DinD prune and maintenance are disabled; currently the claim loops obtain it only from those optional controllers. All run, cross-check and chat claim loops must enter/exit that gate across the HTTP claim and active-set installation.

For a destructive request, close `retained_ops`, wait at most five seconds for `inFlightClaims() === 0`, then reuse `Worker.isIdle()` (all three active sets and the ActiveRunRegistry empty) and require no runner `executionTails`/adoption activity. The gate's in-flight count covers only the claim HTTP/admission window; zero in-flight claims alone is not worker quiescence. Busy, timeout or an unknown observation refuses the request; it does not wait indefinitely for work to finish, cancel a run or stop the worker. Heartbeats and the worker process stay up. Keep the claim gate closed through the operation, take the existing bare/adoption lock and recovery-source operation reservation, and recheck the exact descriptor plus scoped process/container quiescence and absence of live/adopting successor consumers before deletion. Background recovery uses that same reservation/lock; it cannot race the local operation. Do not use server `worker_active_runs` emptiness as a substitute for this local fence, because server snapshots can lag.

Serialize local destructive requests (one active, no unbounded request queue), and release the reservation and only the `retained_ops` gate blocker in `finally` on success, refusal, client disconnect, timeout and shutdown. Refuse new operator operations during shutdown. A disconnected client never authorizes continuing beyond an unverified boundary; report the last exact disposition on a later inspect. Bound request bytes to 8 KiB before parse, response bytes to 64 KiB, descriptor views to 64, and use a single 30-second operation deadline after the five-second idle acquisition. Deadline exhaustion retains any not-yet-disposed source/metadata and returns unknown. Physical deletion uses the existing attributed disposal helper and its process-close proof; timeout is never treated as deletion success.

Reject canonical/current successor paths, sibling generations, shared pins/metadata consumers, replaced descriptors, symlinks and unknown attribution. An operator confirmation authorizes destruction, but never broadens path attribution. Inspection does not close claims unless it needs the same stable snapshot; uncertain live measurements are labelled unknown.

Reuse the existing disposal implementation behind a dedicated explicit local-discard authority, with expected tuple/descriptor and actual-disposal result, rather than raw `rm` in prose. Delete only the exact attributable clone and its exclusively owned retention metadata; keep shared owed/receipt/settlement evidence. Metadata is retired only after verified physical removal; failure leaves a retryable exact-source record. A missing source can be reported lost, but deleting its remaining descriptor still needs the same attribution and consumer checks. Command output distinguishes removed, retained, missing and unknown.

Test inspection and discard at the real GitCache seam and the operator entry point: no-hold and successor-released cases reclaim successfully after confirmation and the live worker's idle/quiescent proof; lack of confirmation, a running writer/container, live successor, changed descriptor and shared metadata all refuse without deletion. Inject an HTTP claim already in flight as the request arrives: the operation either waits for claim completion and then refuses busy, or finishes under the closed gate before a later claim enters; no claim starts between idle proof and deletion. Test all three lanes, a worker without DinD controllers, concurrent requests, background recovery, timeout/disconnect and preservation of another gate blocker. Record the exact production command in the runbook and exercise that same entry point against a disposable fixture, not a hand-written approximation.

## Risks and hosted acceptance handoff

Retention increases ephemeral-storage pressure. On Docker-tier hosted workers, a retained emptyDir clone can be lost on eviction or pod replacement even though its PVC-backed descriptor survives. Existing disk-pressure admission must continue to see the real retained bytes; retain its worker-wide stop on actual capacity pressure. Refusal due only to predecessor identity applies to that retained attempt, not a fresh successor. The tested explicit local discard and bounded count/byte inspection make this state operable without server hold authority. Run-bound ephemeral cleanup can also remove the PVC when no hold remains; report resulting sources as lost. Do not claim retention solves node loss or ephemeral teardown. No new copy store or infrastructure is introduced here.

Hosted acceptance is tracked as an added line on the epic's acceptance issue #2747 once this merges. It is not a worker milestone and carries no sweep eligibility. On isolated hosted resources, record API/worker versions and storage layout; fence a work-bearing flight, verify local-source retention and no stale mutations, restart only its worker process on the same pod and export the bytes. Separately replace only that scratch pod to exercise missing-emptyDir reporting, without claiming byte survival. Verify supported worker cleanup with an existing open hold and distinguish a successor-released hold from proof of the old clone's content. Never delete an unrelated worker or production volume.
