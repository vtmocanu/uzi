## Problem

`api/internal/handler/handler.go` (1744 lines) is the package's wiring file, and its `Routes()` method (`:673-1578`, ~906 lines, nine `*mw.Limiter` parameters) registers every `/api` route group inline: **25 `r.Route(` + 19 `r.Group(` blocks and 35 per-group `r.Use(` guards** (37 `r.Use` in total; the other two are the root `Recoverer`/`RequestID`), one after another, under a single `r.Route("/api", …)` closure (`:678-1575`). Two groups were already extracted as same-package methods — `mountWorkerRoutes(r, proposalLimiter)` (`:1620-1717`, called at `:1573`) and `mountControllerRoutes(r)` (`:1728-1744`, called at `:1574`) — so the package has the pattern; the other ~28 domains never got it. Every route change diffs against all of them, and reading "which guard protects `/repos/{id}/board`" means finding the right closure in 900 lines.

Measured properties that make this a move rather than a design (details in the Decision Log):

- **The root carries no shared middleware except `chimw.Recoverer` + `chimw.RequestID` (`:674-677`)**; there is no `r.Use` at the `/api` level. Every auth guard (`mw.RequireAuth`, `RequireUser`, `RequireAdmin`, `RequireAdminRO`) is applied per group, inline. So each domain block is self-contained: it needs only the bare `/api` router, exactly what `mountWorkerRoutes` receives today.
- **`Routes()` defines no closures or locals to promote** — its only local is `r := chi.NewRouter()` (`:674`); `noLimiter` exists only in comments (a route without a limiter simply omits `.With`). Zero scaffolding beyond method signatures.
- **Nesting is internal to each domain**: the two-level `RequireUser` group + `RequireAuth` group shape appears inside `/me/secrets`, `/admin`, `/repos`, `/workers`, `/runs`, always under that domain's own `r.Route`. No group spans domains.
- **Zero lint findings in `handler.go`** on a clean full run (`GOTOOLCHAIN=go1.26.6 ../scripts/golangci-lint.sh v2.12.2 run ./internal/handler/... --new-from-merge-base= --max-same-issues=0 --max-issues-per-linter=0`); the whole-files ratchet has nothing to drag in.

## Solution

Pure motion, same package. Each domain block moves verbatim into its own unexported method `func (h *Handler) mount<Domain>Routes(r chi.Router, <only the limiters that domain uses>)` in a per-domain file `routes_<domain>.go`; `Routes()` keeps the root router, the four public top-level GETs (`/health`, `/version`, `/branding`, `/branding/logo/{slot}`, `:679-688`) and becomes an ordered list of mount calls (relative order kept where the table keeps blocks whole; the `/me/*` consolidation necessarily reorders, which D4 shows is safe), ending with the two existing mounts. Two blocks — `/runs/*` and `/ws` — **stay inline in `Routes()`** (D5). `Routes()`' signature — nine limiters, their names and order — does not change; it only forwards them.

## Decision Log

- **D1 — methods on `*Handler`, not package functions, not a registry.** The precedent is `mountWorkerRoutes`/`mountControllerRoutes`; the handlers are methods on `h`, so the mount methods need `h`. A table-driven registry or per-domain sub-handler types would be design, and design is out of scope under the freeze.
- **D2 — each mount takes only the limiters it uses; `Routes()` keeps all nine.** Three tests pin `Routes()`' parameter names and order (`TestLimiterNamesCoverEveryRoutesLimiterParameter`, `TestRoutesLimiterParametersAreNamedInLimiterNamesOrder`, and the `cmd/server/main.go` call-site parsers in `route_limiter_mounts_test.go`); the mounts are new and unpinned, so they take the minimum. Nine mounts need zero or one limiter; four (`mountAuthRoutes`, `mountAdminRoutes`, `mountRepoRoutes`, `mountChatRoutes`) take two.
- **D3 — one `r.Route` block is the unit of motion.** A block is never split across files (its nested groups depend on the parent `Route`'s path), and a file may hold several blocks of one domain.
- **D4 — registration order is NOT a preserved property, and it does not need to be.** The `/me/*` blocks are interleaved with six other domains today, so one `mountMeRoutes` cannot reproduce today's order, and fragmenting it to do so would be design-by-accident. Reordering is safe here because every moved block sits under its own distinct static prefix (`/me/secrets` vs `/schedules`, `/me/runs` vs `/runs`, …) and chi matches on a radix tree of patterns, not on registration order, for such prefixes; and no test asserts walk order (`wantRouteMounts` is a set lookup, the bearer-only walk is per-route). Everything else keeps its relative order because that is free.
- **D5 — `/runs` and `/ws` stay in `handler.go` this PRD.** Moving them makes nine test-file sentences false, one of them a runtime error string (`ws_route_guard_test.go:216`); repointing those touches two test files carrying eleven pre-existing gosec findings, which the `whole-files: true` ratchet would turn into a red `task lint:api` for an unattended run. The freeze's proof (zero test edits, zero ratchet exposure) outranks the last 90 lines of extraction; the maintainer follow-up in M4 is the path to finishing it.
- **D6 — `go doc -all` without `-u` is the right byte-identity instrument here**, unlike #1009 (`package main`, `-u` needed): this package has a large exported surface and the new methods are unexported, so the baseline diff is empty only if nothing exported moved or changed doc comment.

## Risks & mitigations

- **A block references a local that the move hides.** Measured none (`Routes()` has no locals beyond `r`); if the compiler finds one, it is a shared helper — promote it to a `Handler` method in its own labelled commit, never inline a copy.
- **Indentation changes defeat `--color-moved`.** Moving a closure body into a method body changes nesting by one level; use `--color-moved-ws=allow-indentation-change` (and state so in the PR) rather than `-w`, which also hides a real whitespace edit inside a line. Neither flag can hide a retyped path — the live-router tests can.
- **A positional comment inside a moved block goes stale** ("the group above", `:NNN`): neither `--color-moved` nor the tests see it; sweep each moved block for `above|below|:\d{3,}` and fix in the same commit, listed in the PR.
- **A path or guard is retyped.** The 227-row limiter-mount table plus the bearer-only walk red-flag any path, guard or limiter change on the first `go test`; a handler rebinding (same path, different method) is the one edit those tests would miss — the `--color-moved` review is the second net, and the PR must say the diff was read for that.
- **`specs/ai.md` numbering collision** with #1007 and #1009 landing the same day: re-derive at landing (M5); the sweep's three runs land in some order and each renumbers above the head it sees.
- **In-flight overlap: none.** No open PR or in-flight PRD touches `api/internal/handler/**` (checked 2026-09-02: #1006 merged; #987/#988/#989 are dependency bumps; #991 is `web/src/mocks`; #1007 is web + `apiTypes.ts` + `uzicli/skill.go`; #1009 is `api/cmd/uzi`).
- **Offline worker.** Nothing here needs the open internet.
