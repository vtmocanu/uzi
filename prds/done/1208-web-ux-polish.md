## Problem

1. **Appearance is buried.** PRD #1167's accepted mock (`prds/mockups/1167-lights-on-themes-mock.html:628`) showed Settings as a tab strip with **Appearance** as its own tab, second after Account & tokens. What shipped folded the Appearance controls and the Demo mode control in as cards **inside** the "Account & tokens" tab (`web/src/pages/Settings.tsx:428` Appearance card, `:562` Demo mode card). The #1167 PRD prose said "card," contradicting its own mock; this PRD resolves that toward the mock.
2. **The board toolbar flings right on wide screens.** On a wide viewport the Board search bar and its controls are pushed to the far-right edge with a large dead gap after the title; the primary Search action ends up on the right instead of the top-left. On a normal-width viewport the toolbar wraps to its own line and left-aligns, which is the wanted look. Root cause below.
3. **"Hide empty" defaults off.** Every board opens showing empty label lanes; the user must tick "Hide empty" each new repo. The preference is already persisted per repo; only the default is wrong.

### Why the board toolbar flings right (root cause)

- The Board renders search + all controls into `PageHeader`'s `actions` slot (`web/src/pages/Board.tsx:1117-…`, inside the sticky wrapper at `:1099`).
- `PageHeader` (`web/src/components/ui.tsx`, `PageHeader`) wraps title-block + actions-block in `flex flex-wrap items-start justify-between gap-x-6 gap-y-3`. When both fit on one line (wide screen), `justify-between` pushes the actions-block — search included — to the right edge, creating the gap. When they do not fit (normal width), the actions-block wraps to its own line and left-aligns. That wrapped, left-aligned look is exactly what the user wants at every width.
- The search input is **not** the `w-44` it appears: `Input`'s base class is `w-full` (`ui.tsx:154`), which wins over the `w-44` override passed at `Board.tsx:1137`, so search renders full-width within its slot. This is why it reads as a full-width bar rather than a 176px box.

**Fix direction (M2):** stop routing the Board toolbar through `PageHeader.actions`. Keep `PageHeader` for the title + description, and render the search + controls as their **own full-width, left-anchored row** directly beneath it, inside the existing sticky container (`Board.tsx:1099`), so the wide-screen layout equals the normal-width layout and search stays anchored top-left (the code already calls search "the primary action", `:1119`). Resolve the `w-full`/`w-44` conflict deliberately: keep the search on its own full-width row (matches the wanted normal-width look) rather than reintroducing a fragile fixed width. The sticky/`z-10`/`bg-ink` behavior must survive unchanged, as must both keyboard affordances: the Escape-clear/blur handler on the input (`~:1130-1135`) and the **id-based `/`-to-focus** — a separate global keydown effect that does `document.getElementById(SEARCH_INPUT_ID)?.focus()` (`~:465`), so it keeps working as long as the moved input keeps its `id={SEARCH_INPUT_ID}` (it is not a React ref).

### Hide-empty default and persistence

- `web/src/pages/Board.tsx:121-129`: `hideEmptyKey = uzi.board.${repoId}.hideEmpty`; `useState(() => prefs.get(hideEmptyKey, false))` (and the repo-swap effect at `:124`), persisted on toggle via `prefs.set(hideEmptyKey, next)` (`:129`). `prefs` is the localStorage-backed preference store.
- **Persistence already works** (per repo, remembered across reloads). The only change is the **default**: `false` → `true` at both the initializer (`:122`) and the repo-swap effect (`:124`). Because `prefs.get` returns a stored value when one exists, a user who previously turned Hide-empty **off** for a repo keeps it off — the default only applies to repos the user never set, which is the correct "default on, respect explicit choice" behavior.
- **The flip breaks existing Board tests** and the worker must fix them in the same milestone, not discover them at the gate. `Board.test.tsx`'s drag-drop / column-label cases rely on empty lanes being *visible* by default: the `aBoard()` fixture has empty lanes (`~:403-410`; only "In Progress" holds a card, "Backlog"/"Planned" are empty), the `beforeEach` (`~:426`) seeds no preference so it reads the default, and assertions like `findByText("Backlog")` (`~:469`), `drop(laneFor("Backlog"), 7)` (`~:476`) and `drop(laneFor("Planned"), 7)` (`~:485`) require those empty lanes on screen. With the default flipped they are hidden and those lookups throw/time out. Fix: seed `prefs.set("uzi.board.repo-1.hideEmpty", false)` (matching the fixture's repo id) in those cases' setup — the dedicated new default-on test is the only case that exercises the flipped default.

- **Six settings tabs** may crowd small screens. The strip already scrolls (`overflow-x-auto`, Issue #204); re-verify 390px in the browser pass rather than assuming.
- **PageHeader is shared.** M2 must change only the Board's use of it (render the toolbar outside `actions`), never `PageHeader` itself, or every other page's header shifts.
- **Spec numbering** (§627) collides if a parallel PRD lands first; renumber on the landing rebase (append-only, check sibling worktrees).
- **Hide-empty default flip** changes the first-open view for existing repos with no stored preference; this is the intent, and an explicit prior `false` still wins, so no one loses a deliberate choice.
- **The flip reddens existing Board tests** that assumed empty lanes render by default (drag-drop / column-label cases). This is the most likely single-run scope-blower if not pre-empted; M3 seeds `hideEmpty=false` in those cases so only the dedicated default-on test reads the flipped default.
- **knip after the move.** Any helper or import left in `Settings.tsx` after its only user moved to `AppearanceSettings.tsx` reddens `task deadcode:web` (gated at `error`).
