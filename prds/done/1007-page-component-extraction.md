## Problem

Two page files carry whole sub-features beside the page:

1. **W6** — `web/src/pages/RunView.tsx` (3213 lines) holds the page (`RunView()` `:763-1435`) plus two self-contained clusters that the page merely renders: the **Plan cluster** (`:1437-1974`, ~538 lines: `MAX_REVISION_ROUNDS`, `PlanRevision`, `derivePlanRevision`, `VersionChip`, `RevisionThread`, `PlanPanel`, `SeededPlanPanel`) and the **Judge cluster** (`:2149-3213`, ~1065 lines: `JUDGE_STAT_K`, `JudgeStat`, `JudgeUsageStrip`, `JUDGE_POLL_MAX_TRIES`, `JudgePanel`, `JustFiled`, `RecommendationFiler`, `DispositionChip`, `resolvedAgo`, `DispositionControls`, `TriageSummary`, `TriageCount`, `TriageMeter`). Measured: **neither cluster references any RunView-local symbol in code** (the only hits — `HealthFlag`, `RunView`, `RunHeading`, `AgentRosterSummary` at `:1730,:1992,:2002,:2011,:2524` — are comments), and the page reaches into the clusters at exactly three JSX sites (`<JudgePanel` `:1335`, `<PlanPanel` `:1338`, `<SeededPlanPanel` `:1361`). Every judge or plan change diffs against a 3200-line page.
2. **W9** — `web/src/pages/Board.tsx` (2370 lines) = the container `Board()` (`:103-1554`, 1452 lines) plus five declarations it only renders: `Highlighted` (`:1556-1581`, unexported, used only by `IssueCard` at `:1817,:1956`), `IssueCard` (`:1583-2039`, exported), `CreateIssueForm` (`:2041-2101`), `IssuesFilter` (`:2103-2192`), `ColumnSettings` (`:2194-2370`) — ~815 lines. `Board()` renders them at `:1132`, `:1259`, `:1272`, `:1366` with inline prop types; the **only** module-level symbol shared across the stay/move line is `COLUMN_ACCENTS` (`:85-86`, unexported; used by `Board()` at `:721` and by `ColumnSettings` at `:2319`). The seven other module consts/helpers (`OPEN_KEY`, `CLOSED_KEY`, `PAGE`, `DEFAULT_PER_LANE`, `PER_LANE_OPTIONS`, `columnKeyForCard`, `columnLabel`) are `Board()`-only.

Both were parked in the epic until #960 established where page-private components live (`pages/adminSettings/`, ten card files, no barrel, no edge back to the shell) and #983 settled the run-kind sites in `RunView.tsx`.

## Solution

Pure motion into two new per-page directories, the #960 M2 recipe: `web/src/pages/runView/` (two files) and `web/src/pages/board/` (four component files + one shared const module). Declarations move verbatim with their doc comments; the only new text is imports, re-exports, the `export` keyword where a moved declaration gains its first cross-file consumer, one shared-const module, and one comment that would otherwise state a falsehood. **Importers stay byte-identical** — every symbol other files import from `./RunView` or `./Board` today is re-exported from the page file — so **no test file changes** (stronger than #960, which needed one). `Board()` and `RunView()` stay where they are; the 1452-line `Board()` container is a later characterization-first PRD (epic decision, deferred past the freeze with `Repos.tsx`).

Then the two leftovers, each a few lines in a file the moves never touch.

**Out of scope**: `Board()` and `RunView()` internals; W10 (the raw `setInterval` judge-verdict poll now at `RunView.tsx:2354`, inside `JudgePanel` — it moves verbatim and must not change behaviour); tightening `runKindLabel`/`isJudgeEligible` parameter types (they take `string` by #983's design); any file under `web/src/mocks/` (#991 owns that tree today).
