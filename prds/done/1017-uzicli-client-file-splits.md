## Problem

`api/internal/uzicli` is the CLI's HTTP client layer: `cmd/uzi` commands take a `Client` interface, tests inject `FakeClient`, and `HTTPClient` serves the real requests (`client.go:19-24`). Two files hold most of the package, and both grow by one method per new CLI verb:

1. **`client.go` (1655 lines)** — three things in one file:
   - the `Client` interface (`:25-436`, 412 lines: **64** methods with their contract doc comments, in an order that already groups by command tree — runs, workers, secrets/tokens, settings, repos, build info, admin, CLI auth, task runs, memory, judge dispositions, schedules, findings, review filing, project sync);
   - the transport core: `ProjectSyncStatus` (`:443`), `ErrNoDisposition` (`:457`), `maxRespBytes`/`logsPageSize`/`maxLogsMessages` (`:462-479`), `HTTPClient` + `NewHTTPClient` + `refuseRedirect` + the interface assertion (`:483-525`), and the request/decode/error helpers `newRequest` (`:535`), `credentialSafeBase` (`:561`), `isLoopbackURL` (`:580`), `doJSONRead` (`:595`), `get`/`postJSON`/`put`/`patch`/`del` (`:625-667`), `decode2xx` (`:678`), `transportMsg` (`:692`), `statusError` (`:702`), `serverErrMsg` (`:752`);
   - **63 exported `(c *HTTPClient)` verb methods** (`:762-1655`; the 64th interface method, `StreamRun`, is implemented in `stream.go:322` and is out of scope) plus three types (`CreateRunSeed :1295`, `ReviewFiledIssueDTO`/`ReviewIssueFileResult :1606-1612`) and two verb-local helpers (`dispositionPath :1014`, `pollStatusField :1279`).
2. **`fake.go` (1073 lines)** — the `FakeClient` struct (`:32-375`, 344 lines of canned-reply and capture fields, each with the doc comment that says which test contract it carries), two capture types (`EnableCatalogCall :379`, `LabelCall :387`), the interface assertion (`:392`) and **64 `(f *FakeClient)` methods** (`:394-1073`, including `StreamRun :1064`) in the same verb order as `client.go`.

The real/fake counts differ by exactly one on purpose: the fake implements `StreamRun` in `fake.go`, the live client in `stream.go`. After the split `fake_runs.go` therefore holds one method (`StreamRun`) with no twin in `client_runs.go`; that is expected, not a leak.

The package around them is already one-file-per-concern (`stream.go`, `authflow.go`, `config.go`, `output.go`, `sanitize.go`, `skill.go`, `skillhook.go`, `versioncheck.go`), and `cmd/uzi` is one file per command tree (`run.go`, `schedule.go`, `review.go`, `findings.go`, `admin.go`, `worker.go`, `repo.go`, …). The client layer is the one place where every tree's verbs sit in a single file, twice.

Measured properties that make this a move rather than a design:

- **Zero lint findings in `client.go` and `fake.go`** on a clean full run at `68ea273` (`cd api && GOTOOLCHAIN=go1.26.6 ../scripts/golangci-lint.sh v2.12.2 cache clean; … run ./internal/uzicli/... --new-from-merge-base= --max-same-issues=0 --max-issues-per-linter=0`): the package's 27 findings are all in `config.go` (3 errcheck), `authflow.go` (3 G204), `skill.go` (G301 `:178`, SA9009 `:13` — both #1007 M4's), `skillhook.go` (2 G301), `stream.go` (G404) and five test files. The `whole-files: true` ratchet therefore drags nothing in: a new file made only of moved code carries 0 findings.
- **Zero test edits needed.** Every consumer takes the `Client` interface or the `FakeClient` type by name; no test globs or reads these files by filename (`filepath.Glob`/`os.ReadDir` in the package: `stream_test.go:838` globs `../store/migrations/*.sql`, `skill_test.go:206` reads the commands dir — neither touches `client.go`/`fake.go`; `cmd/uzi/tui_d7_guard_test.go:142` globs `tui_*.go` in its own package). `client_test.go` (1059 lines) and `stream_test.go` reference package-internal names (`maxLogsMessages`, `statusError`, …), which a same-package move leaves resolvable.
- **The unexported helpers partition cleanly.** Transport helpers (`newRequest` … `serverErrMsg`) are used across every verb and stay; `dispositionPath` (3 call sites, all in the disposition verbs) and `pollStatusField` (1 call site, `PollCLIAuth :1269`) are used by exactly one domain each and move with it. `refuseRedirect`'s one code use is `NewHTTPClient` (`:512`; `stream.go:290` names it in a comment only) — it stays in `client.go`, so nothing outside the two files changes.
- **`go doc -u -all ./internal/uzicli` is layout-independent, full stop.** At `68ea273` it prints 2463 lines (`go doc -all`, exported only: 1914 — blind to `dispositionPath`, `pollStatusField` and the fake's unexported bits, so `-u` is the instrument, PRD #1009 D1). `go/doc` lists funcs, types, each type's methods **and** package-level consts and vars **sorted by name across files** (verified by experiment at authoring: moving `maxLogsMessages` and `ListRuns` into a new file left the output byte-identical; the live output already lists `logsPageSize` before `maxRespBytes`, the reverse of source order). So any declaration moving between files leaves the output byte-identical, and the proof cannot be fooled by placement. The package doc comment lives in `output.go` (`// Package uzicli`), so a new file must not add one (D2).

## Solution

Pure motion, same package, both files split by the same domain map so each real/fake pair sits side by side (`client_runs.go` ↔ `fake_runs.go`). `client.go` keeps everything that is not a verb: the `Client` interface, the DTOs/sentinel/consts, `HTTPClient` and its constructor, and the transport core. `fake.go` keeps the `FakeClient` struct with its field docs, the two capture types and the interface assertion. The verb methods move, byte-identical with their doc comments, into per-domain files.

Never split one domain across files, never move a `const`/`var` (D3), and never change a signature, path, header, body, error message or return.

## Decision Log

- **D1 — `go doc -u -all` is the byte-identity instrument, not `go doc -all`.** The package exports a large surface (1914 lines without `-u`), but two helpers that move (`dispositionPath`, `pollStatusField`) and the fake's unexported bits are unexported and invisible to plain `-all`; `-u` lists every declaration, sorted by name, independent of file (PRD #1009 D1, same reasoning). `go build` + `go vet` + the suites back it up.
- **D2 — new-file headers go below the `package` clause.** The package doc comment lives in `output.go`; a comment above `package uzicli` in any new file becomes a second package doc that `go doc` concatenates, and the proof goes red for a reason that is not a lost symbol. The #963 rule, restated because twelve files give twelve chances to get it wrong.
- **D3 — no `const`/`var` moves, as a scoping rule, not a proof necessity.** `go/doc` sorts consts and vars by name across files exactly as it sorts funcs and methods (measured, see Problem), so moving `logsPageSize`/`maxLogsMessages` to `client_runs.go` would be proof-neutral. The rule exists to keep the split describable in one sentence — "verb methods and their verb-local helpers/types move; everything else stays" — so a reviewer can check the residue against a fixed list instead of a judgment call per const. It costs nothing (`RunLogs` reads the two consts by name from the same package). *(The first draft justified this rule with a source-order claim about `go/doc`; the architect review and the fact-check both refuted it by experiment, and the rule is kept on the simpler ground above.)*
- **D4 — the `Client` interface stays whole and stays in `client.go`.** It is one 412-line declaration whose method order is the contract's reading order, and `go doc` prints an interface body verbatim; splitting it (embedded per-domain interfaces) would be design, and the freeze scopes this epic to motion. The interface-change tax after this PRD is three files (interface, `client_<domain>.go`, `fake_<domain>.go`) instead of two — but each is a fraction of the size, and the pair for a domain is now adjacent in a directory listing.
- **D5 — mirror the domain map on both sides.** A `fake_<domain>.go` beside every `client_<domain>.go` is the point: a reviewer adding a verb touches the interface, one small real file and one small fake file with the same suffix. Splitting only `client.go` would leave the fake as the one 1000-line file in the package.
- **D6 — six domains, named after the `cmd/uzi` command trees**, because those are the files a CLI developer already has open: `run.go` (+ `handoff.go`), `review.go` + `findings.go`, `schedule.go`, `admin.go`, and two bundles of small trees — `account` (`whoami`, `login`, `token`, `memory`, `version`, self settings/rate limits) and `repos` (`repo.go`, `project-sync`, `worker.go`). Not grouped by HTTP method, resource path or DTO package: none of those matches how the package is navigated.
- **D7 — no behaviour, wire-shape or message change.** Any edit found necessary (there should be none) is a separate labelled commit with a test, not part of a move.

## Risks & mitigations

- **A moved declaration is dropped, duplicated or re-documented.** SC2's `go doc -u -all` diff catches all three (a duplicate is a compile error anyway; a drop shows as a `-` line; a doc-comment edit shows as both).
- **A new file gets a comment above `package uzicli`.** D2; the proof goes red immediately, and the fix is to move the comment below the clause. Twelve new files is twelve chances.
- **`fake_runs.go` carries one method more than `client_runs.go`.** `StreamRun` is fake-side only in this split (the live one is in `stream.go`); a reviewer counting pairs sees an odd one out. Expected — SC4 pins 63 vs 64 and the `stream.go` count of 1.
- **A positional comment inside a moved block goes stale** ("the helper above", "below", `:NNN`): neither `--color-moved` nor `go doc` sees it; sweep each moved block for `above|below|:\d{3,}` and fix in the same commit, listed in the PR (the #963 recipe). The `Client` interface doc (`client.go:19-24`, "the live HTTPClient below") stays true because `HTTPClient` stays in the same file.
- **Same package as #1007's `skill.go` edit.** #1007 M4 rewords a doc comment at `skill.go:13` and tightens a mode at `:178` — different file, so no textual conflict; but if #1007 lands first, the branch's post-move `go doc -u -all` will differ from a baseline captured before it. Mitigation: the proof compares the branch's own base capture to the branch's own tip (both taken on the branch), never a capture from `main` at a different commit; if the worker realigns the branch onto a newer `main` (PRD #456), re-capture the baseline at the new base and re-run the diff.
- **`specs/ai.md` numbering collision** with #1007, #1008 and #1009, all in flight and all drafting §597: re-derive at landing (M4); merge order decides, and each renumbers above the head it sees.
- **In-flight overlap: none on the files this PRD touches.** No open PR or in-flight PRD touches `api/internal/uzicli/client.go`, `fake.go`, or their tests (checked 2026-09-02 at `68ea273`: #1007 is `web/**` + `apiTypes.ts` + `uzicli/skill.go`; #1008 is `internal/handler`; #1009 is `cmd/uzi`; #1005's PR #1010 merged as `87a6be5` and touched neither file).
- **Offline worker.** Nothing here needs the open internet; every fact above was measured in the tree at `68ea273`.
