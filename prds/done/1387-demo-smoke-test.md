# PRD #1387: uzi demo smoke test

**Issue**: [#1387](https://github.com/vtmocanu/uzi/issues/1387)
**Priority**: Low
**Status**: Complete

## Purpose

A deliberately trivial PRD whose only job is to exercise the full uzi run loop
(plan, approve, implement, review, branch, MR) end to end. It is a smoke test of
uzi itself, not a product feature. The whole change is one new markdown file at the
repo root, built in three tiny milestones of roughly two minutes each.

> **Scope note (deliberate deviation from the 5-10 milestone guideline).** The
> requester asked for exactly three ~2-minute milestones to test uzi. That override
> is intentional; do not expand the scope or split into more milestones.

## Problem

There is no throwaway, zero-risk target for validating that a uzi run drives a PRD
issue all the way to a merge request. Real feature PRDs are the only current way to
test the loop, which is heavier and riskier than a smoke test needs to be.

## Solution

Create a single self-contained file, `DEMO.md`, at the repository root, and build it
up over three small milestones. The file touches no code, no `docs/` pipeline, no
`prds/`/`adr/` link checks, and no `.github/workflows/**`, so it clears every
repo-wide gate (shellcheck, yamllint, secret scan, semgrep, no-binary-text) trivially
and cannot redden `main`.

## Constraints (offline worker)

- **Everything here is resolvable offline.** No open-web lookup is required to
  complete any milestone. The only file created lives at the repo root and is written
  from the literal content specified below.
- **Do not touch `.github/workflows/**`.** The worker PAT lacks `workflow` scope; any
  workflow-file change in the branch diff is an atomic push rejection that loses the
  whole branch (see `.claude/rules/prds.md`).
- **Root file only.** `DEMO.md` at the repository root is intentionally outside
  `docs/`, `prds/`, and `adr/`, so none of the docs-frontmatter, `docs:sync`
  byte-equality, or backticked-path checks apply to it. Do not add frontmatter and do
  not run `task docs:sync`.
- **No source code, so no new tests.** This is a markdown-only change; the repo's
  bug-fix regression-test rule does not apply (there is no code seam to pin). Validation
  is that the file exists with the expected sections and the repo gates stay green.

## Target file content

The final `DEMO.md` after all three milestones should read approximately as:

```markdown
# uzi demo

This file was produced by a uzi run as an end-to-end smoke test of the run loop
(plan, approve, implement, review, merge request). It is safe to delete.

## What this demonstrates

- uzi can take a PRD issue from plan to an approved, implemented merge request.
- A milestone-structured issue run completes each milestone in sequence.
- The repo-wide CI gates pass on a clean, self-contained change.

---

Generated by uzi for issue #1387. Safe to revert once the demo is confirmed.
```

Exact wording is not load-bearing; the section headings and structure are.

## Milestones

- [x] **M1: Create `DEMO.md` with a title and one-paragraph description.**
  Create `DEMO.md` at the repo root containing a top-level `# uzi demo` heading and a
  single paragraph explaining that the file was produced by a uzi run as an end-to-end
  smoke test and is safe to delete.
  *Validation*: `DEMO.md` exists at the repo root, starts with `# uzi demo`, and the
  repo gates stay green.

- [x] **M2: Add a "What this demonstrates" bulleted list.**
  Append a `## What this demonstrates` section to `DEMO.md` with three short bullet
  points (plan-to-MR loop, milestone-by-milestone completion, gates stay green).
  *Validation*: the section and its three bullets are present below the M1 content.

- [x] **M3: Add a footer note.**
  Append a horizontal rule and a one-line footer to `DEMO.md` stating it was generated
  by uzi for issue #1387 and is safe to revert once the demo is confirmed.
  *Validation*: the footer line is the last content in the file; the file reads
  top-to-bottom as heading, paragraph, list, rule, footer.

## Success criteria

- `DEMO.md` exists at the repo root with all three sections (heading + paragraph,
  bulleted list, footer).
- The branch opens a merge request with no `.github/workflows/**` in its diff.
- CI is green on the MR (the change is markdown-only and clears every gate).
- The change is trivially revertible (a single-file delete).

## Risks and mitigations

- **Risk**: an accidental edit outside `DEMO.md` trips a component gate.
  **Mitigation**: the milestones are scoped to the one root file; touch nothing else.
- **Risk**: the file is mistaken for a real doc.
  **Mitigation**: the content and this PRD both state it is a smoke-test artifact,
  safe to delete/revert.

## Decision log

- **Single root markdown file, not code or `docs/`.** Chosen because it clears all
  repo-wide gates trivially, needs no tests, and avoids the docs-frontmatter /
  `docs:sync` / link-check machinery. The point is to test uzi's loop, not to add
  product surface.
- **Three milestones on one file, done in sequence.** Matches the requester's
  explicit ~2-minute-each, three-milestone ask; exercises milestone-structured run
  completion without cross-file coordination.
