## Problem

`api/internal/settings/settings.go` is 1958 lines and holds four different things: the settings **schema** (two key/default const blocks `:39-374`, `Defaults` `:412`, `SecretKeys` `:520`, `IsSecret` `:532`, `Known` `:540`), the **`Cache` engine** (`Store` `:550`, `Cache` `:558`, `New` `:582`, `snapshot`/`get`/`effective`/`source`/`configured` `:610-698`, `intSetting`/`boolSetting`/`secret` `:1191-1254`, `SealSecret`/`DecodeSecret`/`ValueForStorage` `:1254-1293`, `All`/`AdminView`/`Effective` `:1293-1360`, `Validate` `:1360`), some **fifty typed accessors** (`:705-1191`) and some **twenty-five validators plus their bounds consts** (`:374-412`, `:1433-1958`) for a dozen unrelated domains: agent-source sync, release check, run labels, branding, run health, judge, hosted workers, MR rework, the docker repo allowlist, Slack. The package's tests are already cut per domain (`settings_agent_source_test.go`, `settings_branding_test.go`, `settings_health_test.go`, `settings_hosted_test.go`, `settings_release_check_test.go`, `settings_slack_test.go`, `settings_docker_allowlist_test.go`, `settings_capability_test.go`, `settings_github_project_sync_test.go`, `selfimprove_pin_test.go`, plus the core `settings_test.go`); the source is the only thing not.

## Solution

Pure motion, same package. **No exported-API change, no behavior change, no test edit.** The schema moves to `keys.go` as one unit; each domain's accessors, bounds consts and validators move verbatim into `settings_<domain>.go`, named after the test file that already exists for it; `settings.go` keeps the package doc comment (`:1-11`, above `package settings` at `:12`), the `Cache` engine, `Validate`, the generic validators and the handful of one-accessor keys that have no domain. Each file's only new text is its package clause, imports and a two-line header comment placed **below** the package clause after a blank line (the #963 rule: a comment above `package settings` in a new file becomes a second package doc comment that `go doc -all` concatenates and breaks the byte-identity proof).

## Decision Log

- **D1: the schema is one file, not scattered per domain.** `Defaults`, `SecretKeys` and `Validate` each enumerate every key; the key consts are also what `handler/settings.go`, `workersvc` and the CLI import by name. A reader asking "what settings exist" wants one file, and per-domain keys would put the same `PRD #NNN` comment blocks in twelve places. `Validate` stays with the engine for the same reason: it is the one place every key is dispatched.
- **D2: domain files are named after the test files that already exist.** `settings_agent_source_test.go` gains `settings_agent_source.go`, and so on; the three domains with no test file of their own (`labels`, `judge`, `mr_rework`; all three are covered by the core `settings_test.go`) follow the same `settings_<domain>.go` shape. Not `keys_<domain>.go`, not a `domains/` subpackage: same package, same prefix, so `ls` groups them.
- **D3: bounds consts travel with their validator.** `healthSecondsMin`/`Max`, `maxHostedWorkerQuota`, `maxJudgeDailyBudget`, `maxMrReworkCap`, `maxLabelLen` (`:374-412`) each have exactly one validator reader plus one accessor reader in the same domain (measured); leaving them in `keys.go` would make the schema file carry validation policy.
- **D4: `validateModelAlias` goes to the judge file, not `settings.go`.** It validates only `judge_model` and `summary_model`, and `SummaryModel` "mirrors `judge_model`'s settings machinery … but rides the ISSUE-RUN claim" by its own key comment (`:76-80`), so the two model accessors and their validator are one family. `validateBool` and `validateEnum` stay generic because seven and three keys across five domains use them.
- **D5: move-only commits, one file per commit, no folded improvements.** The reviewability of pure motion is the entire safety argument (#921 D2); anything noticed during the move (a duplicated switch, a stale comment beyond position) is filed, not folded.
- **D6: `go doc -all` without `-u` is the byte-identity instrument.** The package has a large exported surface and nothing unexported is promoted, so the baseline diff is empty only if no exported declaration moved out of the package or changed its doc comment; unexported moves are invisible to it by construction, which is what the `--color-moved` review covers.

## Risks & mitigations

- **A moved validator references a helper the table left elsewhere.** Same package, so it compiles regardless; the risk is cohesion, not correctness. The caller map above says none does; if the implementer finds one, it moves with its single caller, and the commit message says so.
- **A positional comment inside a moved block goes stale.** Neither `--color-moved` nor the tests see it; sweep each moved block for `above|below|:\d{3,}|this file` and fix in the same commit, listed in the PR.
- **`goimports` drops an import the moved code needed, or `settings.go` keeps one it no longer needs.** `task fmt-check:api` and the compiler catch both; do not hand-edit import blocks beyond what the compiler asks for.
- **`specs/ai.md` numbering collision** with #1008, #1009, #1017 and #1022 landing the same night: re-derive at landing (M4); the sweep's runs land in some order and each renumbers above the head it sees.
- **In-flight overlap: none.** No open PR or in-flight PRD touches `api/internal/settings/**` (checked 2026-09-02 at `3c03565`: #1008 is `handler.go` + `routes_*.go`, #1009 is `api/cmd/uzi`, #1017 is `api/internal/uzicli`, #1022 is `handler/schedules.go` + `workers.go` + `runs.go`; #1019 touched `handler/notifications.go`).
- **Offline worker.** Nothing here needs the open internet.
