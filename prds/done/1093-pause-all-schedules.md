## Problem

Skipping one night of scheduled runs means pausing every schedule row by hand: on this instance that is seven catalog defaults plus the owner's own schedules, across every repo, and then remembering which rows were on when resuming. There is no user-wide switch (verified: `api/internal/settings/keys.go` has only the admin-wide `capability_aware_scheduling` key, unrelated; `UZI_SCHEDULER_CHECK_INTERVAL=0` disables the scheduler goroutine for **everyone**, an operator lever). The failure mode of a plain boolean would be forgetting to flip it back and silently losing days of sweeps, so the switch needs an auto-resume time.

## Solution

One **user-level** switch that pauses every schedule the user owns, on every repo, catalog defaults and user-authored alike, with an optional **auto-resume instant**.

1. **State**: two additive columns on `users`: `schedules_paused boolean NOT NULL DEFAULT false` and `schedules_paused_until timestamptz NULL`. Paused means `schedules_paused AND (schedules_paused_until IS NULL OR schedules_paused_until > now())`. `until` NULL = "until I resume". An expired `until` reads as not paused everywhere (no background job clears it; reads normalize).
2. **Enforcement at fire time, in the scheduler**, not by filtering `ClaimDueSchedules`. In `process`, after the claim and before `fireOne`, resolve the owner's pause state (one lookup per distinct `UserID` per tick, memoized for the tick). If paused:
   - a **recurring** row records `FireOutcome{Matched: 1, Skips: [{Reason: SkipSchedulesPaused}]}` and **advances** as a benign outcome, exactly like the vault-lock precedent. The cadence keeps ticking, so resuming never replays a burst of missed fires (the property #396 established for per-row resume), and the row's Last run explains **why** nothing ran instead of showing nothing.
   - a **once** row is **left un-advanced and unwritten** (the transient branch's behaviour: log only). It stays overdue and fires on the first tick after the pause ends, matching `docs/scheduling.md` "Restarts and missed fires" for a one-time schedule left overdue.
   - `RunNow` (`POST /schedules/{id}/run-now`) is untouched: a manual fire bypasses the switch. Runs already in flight are never touched (a pause is not a cancel, same as per-row pause).
   - per-row `enabled` is never written by pause-all or resume-all, so resume restores the exact prior set.
3. **New skip reason** `schedules_paused` in the closed set, with its web label ("all schedules paused"), neutral tone (benign, self-resolving) and CLI label. A paused fire's Last fire detail in the web shows one explanatory row ("All your schedules were paused when this fire came due (until …). The cadence advanced as normal; nothing replays on resume.") instead of a candidate list.
4. **API**: a singleton resource under the existing `RequireUser` schedules group (CLI-reachable), registered ahead of `/{id}` like `/preview`:
   - `GET /api/schedules/pause` → `{"paused": bool, "until": "<RFC3339>"|null}` (normalized: an expired until returns `paused:false, until:null`).
   - `PUT /api/schedules/pause` body `{"until": "<RFC3339>"|null}` → pauses; `until` in the past is `422`; returns the state.
   - `DELETE /api/schedules/pause` → resumes (idempotent); returns the state.
   New DTO `apitypes.SchedulePauseDTO`, contract fixtures `fixtures/api-contract/schedule_pause.{zero,full}.json`, `web/src/lib/apiTypes.ts` type. Owner-scoped by construction (the row is the caller's own user).
5. **CLI** (`api/cmd/uzi`): `uzi schedule pause-all --until <when>` (flag **required**, so a bare `pause-all` never silently means forever; `<when>` accepts RFC3339, a Go duration such as `24h`, `tomorrow[ HH:MM]`, a weekday name `[ HH:MM]` (default `09:00`), or `never`; relative forms are resolved **client-side in the local timezone** and sent as RFC3339), `uzi schedule resume-all`, `uzi schedule pause-status` (the read; `--json` on all three emits the DTO). `uzi schedule list`'s NEXT column reads `paused (all) until <stamp>` (or `paused (all)` for indefinite) while paused; a row that is itself paused keeps `paused` in ON. `list --json` stays an array (unchanged). The embedded skill `api/internal/uzicli/skill/SKILL.md` documents the verbs (the drift test forces it) and `docs/cli.md` follows.
6. **Web** (`web/src/pages/Schedules.tsx` and friends), matching the reviewed mock:
   - **Running**: the header keeps its single line (title, description, `New schedule` top-right). A `Pause all ▾` secondary **sm** button sits at the **right end of the tab row** (`ml-auto`), directly under `New schedule`, so no height is added to the header.
   - **Picker**: clicking it opens an **inline panel in the banner slot** between the header and the tab row (nothing on the page is covered): warn-toned card, title "Pause all schedules", one sentence of scope ("Every schedule you own, on every repo, default jobs and your own. Per-schedule switches are left as they are. Run now still works; runs already in flight are not stopped."), a radio group of presets, each with its resolved time in mono faint text: **Until tomorrow 09:00** (default), **For 24 hours**, **Until Monday 09:00** (the next Monday 09:00 strictly after now, the same rule as the CLI's weekday form), **Until I resume**, **Custom date & time…** (a `datetime-local` input, browser timezone), then `Cancel` and a primary `Pause all until <short stamp>`.
   - **Paused**: the tab-row button disappears and the same slot shows a warn-toned banner: bold "All schedules paused until <stamp> (in Xh)" (or "until you resume them"), the scope sentence, and two actions: `Change…` (reopens the panel) and primary `Resume now`. One control per state.
   - Every Next-run cell (`DefaultJobs` summary `nextCell`, `ScheduleGroupRow` sub-row line, the custom rows) shows a warn-coloured "paused until <stamp>" line under its pill or in place of "· next …"; per-row toggles stay as they are (visibly on).
   - `LastRun.tsx`: label + neutral tone for `schedules_paused`, and the explanatory detail row from point 3.
   - Mock mode (`web/src/mocks/mockApi/schedules.ts`): `getSchedulePause` / `putSchedulePause` / `deleteSchedulePause` with in-memory state so the flow works under `VITE_UZI_MOCK=1` with no new scenario name.

Out of scope (recorded so nobody widens the PRD): an admin-global twin (the `users.mr_rework_enabled` + `app_settings` pattern of migration 00165 is the template if ever wanted), a per-repo pause, and notifications on pause or auto-resume (D10).

## Decision Log

- **D1 — user-level scope, every repo, both origins; no admin twin.** The ask is "tonight I want nothing to run"; a per-repo or per-origin switch reintroduces the bookkeeping the feature removes. An instance-wide admin switch is a separate, cheap follow-up on the 00165 pattern.
- **D2 — `until` auto-resume is part of v1, stored as `schedules_paused` + nullable `schedules_paused_until`.** A plain boolean's failure mode is forgetting it. Two columns rather than one `timestamptz` with `'infinity'`: no infinity plumbing through pgx and JSON, and "until I resume" is an honest NULL. Expiry is computed on read and at fire time, so no sweeper or cron is needed.
- **D3 — enforce at fire time in the scheduler; recurring rows skip-and-advance, once rows wait.** Filtering the due query would leave every recurring row overdue and replay a burst on resume (the exact defect #396 fixed per row). Recording a typed skip and advancing mirrors the vault-lock precedent and keeps the fire visible in Last run. A `once` row is different: advancing it would consume it silently, so it is left overdue (the transient-branch behaviour) and fires after resume, the same semantics as a restart-missed one-time schedule. Cost: an overdue once row is re-claimed each tick while paused; that is one row lock and one memoized user lookup per tick per once row, bounded and cheap.
- **D4 — per-row `enabled` is never written by pause-all / resume-all.** That is the whole gain over bulk-flipping rows.
- **D5 — `run-now` bypasses the switch; in-flight runs are untouched.** A manual fire is an explicit act; the switch is about unattended fires. `RunNow` already neither advances nor parks, so it needs no change. A pause is not a cancel (the per-row `pause-does-not-touch-in-flight-run` test's semantics extend unchanged).
- **D6 — a new `SkipReason` (`schedules_paused`) rather than a new `LastFire` field.** The closed set already has a cross-language drift test, generic rendering in web and CLI, and the vault-lock precedent of a candidate-less user-level skip with `Matched: 1`. A new top-level field would need DTO, fixture, web type and bespoke rendering for one case.
- **D7 — dedicated singleton routes under `/api/schedules`, not `PUT /api/me/settings`.** `PUT /me/settings` is cookie-only (`RequireAuth`), so the CLI could not reach it; the schedules group is already `RequireUser`. Singleton `GET/PUT/DELETE` maps one-to-one onto `pause-status` / `pause-all` / `resume-all` and avoids merge semantics on the settings blob. A router-level auth test guards the mount (the uzi-cli skill's plan-trap).
- **D8 — relative `--until` forms resolve client-side in the local timezone; the server accepts RFC3339 or null only.** The server stays timezone-free and validates one shape; the CLI and the browser each know the user's local time. `--until` is required so a bare `pause-all` cannot silently mean forever.
- **D9 — UI placement, from the reviewed mock.** Header stays one line; the control lives at the right end of the tab row under `New schedule`; the picker is an inline panel in the banner slot (a dropdown covered the "Enable a default on your repos" card); while paused the button yields to the banner carrying `Change…` / `Resume now`, one control per state. Default preset is "Until tomorrow 09:00" because "tonight" is the motivating case.
- **D10 — no notifications in v1.** The user flipped the switch themselves; the banner and the skip records are the feedback. If an auto-resume notice is wanted later, the `park()` notice in `scheduler.go:742-761` (`notifysvc.Notification` + `SlackRender`) is the shape to copy.

## Risks & mitigations

- **Forgetting to resume.** Mitigated by the `until` presets (default tomorrow 09:00), the banner on the Schedules page, and `schedule list` reading `paused (all)`.
- **Clock and timezone edges in `--until` resolution** (DST transitions, "tomorrow 09:00" across midnight). Table tests with fixed clocks and a DST-crossing case in M3; the server never interprets relative forms (D8).
- **Once rows overdue for a long pause.** Re-claimed each tick, bounded by the count of once rows; the lookup is memoized per tick. If a deployment ever has thousands of once rows, a `WHERE` on the join is the escape hatch; not needed now.
- **Owner lifecycle.** A hard-deleted user cascades its `run_schedules` rows (`00103_run_schedules.sql:16`, `ON DELETE CASCADE`), so a claimed row always has an owner; a deactivated user keeps its row and its pause state. `GetUserSchedulePause` returning `ErrNoRows` resolves to not paused (fail-open, M1). Schedule ownership is immutable in uzi (no reassignment path), so "owner changes mid-pause" is out of scope, not a risk.
- **Sweeper and heartbeat interplay.** None: the run-lifecycle sweeper acts on `runs`; the pause path creates no run and touches none.
- **Skip-reason mirror drift.** Forced by `scheduleSkipReasons.test.ts` (reads the Go source) and by `LastRun.tsx`'s exhaustive tone map (a tsc error); the CLI label map is covered in M3's tests.
- **Contract fixtures.** Re-record from the Go contract test output per `fixtures/api-contract/README.md`; hand-authored fixtures are a known trap.
- **Mock mode drift.** The mock api gains the three methods with in-memory state; `Schedules.test.tsx` runs against it, so a missing method reddens the gate.
- **Migration numbering collision.** Draft `00189`; renumber at merge above the live head; `gate:repo`'s `check:migration-numbering` catches duplicates.
- **Copy-change negative assertions.** M4 greps retired strings across the web test tree before finishing (`.claude/rules/web.md`).
