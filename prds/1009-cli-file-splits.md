## Solution

Same-package moves in three areas, then one constructor extraction that follows the package's own precedent:

```
api/cmd/uzi/run.go                 newRunCmd + run-only plumbing        (~1000 after M1; ~350 after M4)
api/cmd/uzi/run_shared.go          non-render helpers used from another tree: readPlanFile, resolveMessage
                                   (handoff.go), mrReworkFlag (schedule.go)
api/cmd/uzi/run_wait.go            runWait, maxPlanSeq, waitTargets, waitOrDeadline (run_wait_test.go exists)
api/cmd/uzi/run_render.go          renderRunDetail + its rows (limitWaitRows, milestoneRows, summaryRows,
                                   deltaGlyph, credentialCell, selectReasonText, limitWaitLine, resumesIn, fmtUntil),
                                   renderMessage/actorCell/compactPayload/renderRunInputs/steer*
api/cmd/uzi/render.go              (existing) + the package-wide cell helpers: cellText, compactText, relAge,
                                   capCell, shortRecID, shortInstanceID, effectiveRunStatus, sanitizeTTY
api/cmd/uzi/review_render.go       renderReview, triageLine, coordKey, dispositionsByCoord, dispositionSuffix,
                                   pendingJudgePhrase (consumed by review.go + tui_review.go)
api/cmd/uzi/run_<sub>.go           M4 only: one constructor per subcommand cluster (see M4)
api/cmd/uzi/schedule.go            tree + subcommand constructors (~740)
api/cmd/uzi/schedule_request.go    request builders: buildScheduleRequest, buildScheduleEditRequest,
                                   buildDefaultScheduleEditRequest, parseAt (~350)
api/cmd/uzi/schedule_catalog.go    catalog subtree (+ guardrail helpers)
api/cmd/uzi/schedule_render.go     renderers + skip-reason maps
api/cmd/uzi/tui_detail.go          state, keys, header/render/footer
api/cmd/uzi/tui_detail_rail.go     lane rail + milestones
api/cmd/uzi/tui_detail_meters.go   spend/rate meters
api/cmd/uzi/tui_detail_transcript.go transcript build/render + tool-frame helpers
api/cmd/uzi/tui_board.go           state, keys, renderBoard/boardItem, version readout, toggles/window/scroll
api/cmd/uzi/tui_board_rows.go      rate-limit strip, empty/paint/row rendering, markers
api/cmd/uzi/tui_text.go            shared visual helpers from both: clampVisual, padVisual, visualWidth, padCell,
                                   paintSeg, padSeg, itoa, shortDuration, runDuration, shortRunID
```

**Every new file split out of the two TUI files keeps the `tui_` prefix** (the D7 guard glob). The exact grouping is the implementer's call within these rules: a helper used from more than one command tree goes to a shared file, never duplicated; a helper used by one tree stays with it; no file over ~1000 lines; declarations move byte-identical with their doc comments; new-file header comments go **below** the `package main` clause after a blank line (the package doc comment lives in `main.go:1-5`; a comment above `package main` in a new file becomes a second package doc that `go doc` concatenates and breaks D1's proof).

**Out of scope**: `api/internal/uzicli/**` (the HTTP client layer is a separate package; `client.go` 1655 / `fake.go` 1073 are measured, not scheduled); `api/cmd/uzi/skill.go`, `root.go`, `tui.go` and every file not named above; any flag, output, or behaviour change; `docs/cli.md` (it names none of the four files).

## Decision Log

- **D1 — `go doc -u -all` is the byte-identity instrument, not `go doc -all`.** `package main` exports almost nothing; without `-u` the baseline is 73 lines and a dropped or duplicated helper is invisible to it. With `-u` every declaration is listed, ordered by name, independent of file — the same "did every symbol survive" question #921/#963 asked of an exported surface, asked of an unexported one. `go build ./cmd/uzi` + `go vet` + the suite (which references most helpers by name) back it up.
- **D2 — consolidate the shared render helpers instead of scattering them.** `run.go` is a de-facto library for the TUI, `schedule`, `review` and `admin`; moving each helper next to its "first" consumer would put `cellText` in a TUI file and `renderReview` in `run_render.go`. `render.go` already exists for exactly this and stays the home of the cell helpers; review rendering gets its own file beside `review.go`.
- **D3 — the `tui_` prefix is a contract, not a naming taste.** `tui_d7_guard_test.go` discovers TUI sources by glob; a file named `board_rows.go` would be TUI code the D7 sanitizer guard no longer sees, with the test green. The prefix rule is stated in three places in this PRD on purpose.
- **D4 — M4 is extraction and is last.** Wrapping each subcommand literal in a constructor is what `schedule.go` already does, so it follows the package's own convention rather than inventing one; but it is not byte-motion, so it gets its own proof form (additions-only `go doc -u` diff + the by-name tree test) and sits after the three pure-motion milestones so they can land without it if it goes sideways.
- **D5 — `api/internal/uzicli/` stays out.** Different package, different proof surface (`go doc -all` works there), and `skill.go` in that package belongs to #1007 this week. Measured sizes recorded in Problem for a later PRD.
- **D6 — no behaviour, flag or output change.** Any output string edit found necessary (there should be none) is a separate labelled commit with a test, not part of a move.

## Risks & mitigations

- **A helper is moved twice or dropped.** `go doc -u -all` diff (SC2) catches both — a duplicate is a compile error anyway, a drop shows as a `-` line.
- **A TUI file loses the prefix.** SC4 plus the recorded D7 file list; the guard's own vacuity check only fires when zero files match, so the PR evidence is the control.
- **M4 changes behaviour through evaluation order.** Flag vars declared inside a constructor are initialised per call exactly as they were per `newRunCmd` call today (the tree is built once per `Main`); `TestCommandTree` and the per-subcommand tests pin names, flags and outputs. If a literal turns out to read a `newRunCmd` local that is not its own flag var, M4's scope cap applies.
- **Stale positional comments inside moved blocks** ("the helper above/below", `:NNN`) — neither `--color-moved` nor `go doc` sees them; sweep each moved block for `above|below|:\d{3,}` and fix in the same commit, listed in the PR (the #963 recipe).
- **`specs/ai.md` numbering collision** with #1007/#1008 landing the same day — re-derive at landing (M5).
- **In-flight overlap: none.** No open PR or in-flight PRD touches `api/cmd/uzi/**` (checked 2026-09-02: #1006 merged; #987/#988/#989 are dependency bumps; #991 web mocks; #1007 web + `apiTypes.ts` + `internal/uzicli/skill.go`; #1008 `internal/handler`).
- **Offline worker.** Nothing here needs the open internet.
