## Problem

## Decision Log

- **D1: one PRD for two files, because it is one recipe in one package with one proof.** Both files split by the same discipline, land under the same `go doc -all` baseline and the same test suite, and are file-disjoint from every in-flight PRD; two PRDs would double the baseline captures and the `specs/ai.md` renumbering for no review benefit. The commits stay per-file (eight move commits + one comment commit), so review is still per-theme.
- **D2: the run handlers go to `runs_lifecycle.go`, not into `runs.go`.** `runs.go` already exists as the two listings (`ListRuns`, `AdminListRuns`); folding 680 lines of lifecycle into it would recreate a 800-line mixed file. `runs.go` keeps the listing role, `runs_lifecycle.go` gets create/get/messages/input, `runs_dto.go` gets the mapper the nine other files call. `AdminListWorkers` moves the other way because it is a worker listing calling `workerDTOFromWorker`; its home was an accident of the admin surface landing in `runs.go`.
- **D3: the eight pointer helpers stay in `handler` (`pgptr.go`), not in `pgconv`.** They are the read-side inverse of `pgconv`'s write-side constructors, but there is exactly one definition site (`git grep -n -P '^func (textPtrValue|uuidPtrValue|timePtr|intPtrValue|boolPtrValue|int8PtrValue|float4PtrValue|int32PtrValue)\(' -- 'api/**/*.go'` → `workers.go` only), and a promotion means exporting eight names and touching eleven files; that is a dedup PRD with the rubric's 3+ bar unmet, not motion. A `pgptr.go` in `handler` gives them a truthful home and leaves the promotion as a one-file move for whoever finds a second site.
- **D4: shared schedule helpers stay in `schedules.go`.** `scheduleParam`, `scheduleLabelsToSlice`, `marshalLabels`, `MaxGuidanceBytes` and `MaxSweepIssues` are called from more than one seam (measured above), and the #963 rule is that a helper serving several seams stays in the base file; `runNowResponse` and `schedulePreviewCap` stay for the opposite reason: their sole callers (`RunScheduleNow`, `PreviewSchedule`) are base-file handlers. `scheduleDTO` and `repoPathFor` are the exception in the other direction: eight and six callers across three seams make them a seam of their own, so they get `schedules_dto.go` rather than bloating the base.
- **D5: the M5 comment repoints are allowed, and #1008 D5's reasoning is why.** #1008 left `/runs` + `/ws` inline because repointing their test comments would have edited `ws_route_guard_test.go` (4 gosec findings) and `cli_auth_livedb_test.go` (7), and `whole-files: true` would have gated all eleven. The two test files this PRD repoints (`runs_test.go`, `guard_role_notify_test.go`) carry 0 findings, so the same rule permits the edit here; keeping them in one clearly labelled comment-only commit keeps the pure-motion proof intact for the other eight.
- **D6: `go doc -all` without `-u` is the byte-identity instrument** (#1008 D6): the package's exported surface is the handlers, every one of which moves unchanged; go/doc sorts by name, not file, so a moved exported method leaves the output identical (the #921 and #963 result).

## Risks & mitigations

- **A moved handler references an unexported helper the table left in another new file.** Same package, so it compiles regardless; the risk is only cohesion. The caller maps say the table is consistent; if the implementer finds a miss, the helper follows its callers and the commit message says so.
