## Problem

The `forge` package already knows how to split a driver: `github_pipelines.go` (675 lines) and `forgejo_pipelines.go` (228) hold the CI/pipeline method group of their driver, and `projectsync.go` (826) holds the GitHub `ProjectBoardSyncer` methods. Everything else each driver does still sits in one file: **`github.go` is 1314 lines** (27 `*github` methods, 10 unexported functions, 2 GraphQL types) and **`forgejo.go` is 1241** (28 `*forgejo` methods, 9 unexported functions, 5 types). Because all three drivers implement the same `Forge` interface, the same method groups exist in each, so one seam map fits both large drivers; `gitlab.go` (821) is under the epic's bar and is the only driver whose pipeline reads are still inline.

## Solution

Pure motion, same package. **No exported-API change, no behaviour change, no test-code edit.** Each seam moves verbatim into its file; the only new text is each file's package clause, imports and a two-line header comment placed **below** the package clause after a blank line (the #963 rule; `go doc -u -all` concatenates a comment placed above `package forge` into the package doc, which would break the byte-identity proof).

## Decision Log

- **D1: `go doc -u -all` is the byte-identity instrument, and `go doc -all` is rejected.** Measured at `c1026a3`: `go doc -all ./internal/forge | grep -c '^func (g \*github)'` → 0; with `-u` → 55. The package's exported surface is the `Forge` interface and the domain types in `forge.go`, none of which this PRD touches, so `-all` would stay byte-identical even if a driver method were deleted. #963's command is right for `forgesvc` (exported `ProjectSyncService`) and wrong here; #1009 already made the same switch for `package main`.
- **D2: `checkForgejoVersion` stays in `forgejo.go` although its only caller (`VerifyToken`) moves.** Five present-tense anchors outside the package (`specs/ai.md:11880`, `:17904`, `agentsource/lsremote.go:178`, `uzicli/versioncheck.go:19`, `workersvc/upgrade.go:88`) cite "`forge/forgejo.go`'s `checkForgejoVersion`" as the in-repo precedent for a two-line version guard; keeping it in the base file keeps all five true at the cost of one cross-file call, which is the cheaper side of that trade. It also sits naturally beside `newClient`, the other constructor-adjacent helper.
- **D3: `gitlab.go` gets the pipelines extraction only.** At 821 lines it is under the epic's bar; the one move that adds value is parity with the two existing `_pipelines.go` siblings, so every driver's CI reads live in the same-named file. A full seam split would move `DefaultBranchProtection` and falsify the two `gitlab_test.go` comments, and repointing them would edit a test file carrying 4 gosec findings, which `whole-files: true` would then gate (the #1008 D5 trap). Pipelines-only avoids both.
- **D4: cross-driver symbols stay where they are.** `maxTraceBytes` is declared in `gitlab.go` and read by all three drivers; `repoSlug` is declared in `forgejo.go` and returned by `github.repoSlugFor`; `sameNameSet` is declared in `forgejo.go` and called by both drivers' `UpdateIssueLabels`. Moving either to `forge.go` would be a reasonable tidy-up but is a placement decision across drivers, not motion within one; it stays out so the diff is provably a split. A follow-up may do it as a two-line move.

## Risks & mitigations

- **A moved method references a helper the table left in another new file.** Same package, so it compiles regardless; the risk is only cohesion. The caller map says the table is consistent; if the implementer finds a miss, the helper follows its callers and the commit message says so.
- **A positional comment inside a moved block goes stale** (`github.go:1203` is one known instance). Neither `--color-moved` nor the tests see it; sweep each moved block for `above|below|:\d{3,}|this file|in (github|forgejo|gitlab)\.go` and fix in the same commit, listed in the PR.
- **`goimports` drops an import the moved code needed, or the source file keeps one it no longer needs.** The compiler and `task fmt-check:api` catch both; do not hand-edit import blocks beyond what the compiler asks for.
- **The header comment lands above `package forge` and changes the package doc.** SC2 catches it (`go doc -u -all` diff non-empty); the header goes below the package clause after a blank line.
- **`specs/ai.md` numbering collision** with #1009, #1017, #1021, #1022 and #1026 landing the same night: re-derive at landing (M5).
