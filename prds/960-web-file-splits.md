## Problem

Three of the six largest hand-written files in the repo are in `web/`, and each is one file only by accretion:

1. **W4** — `web/src/lib/api.ts` (4093 lines) holds **153 exported DTO `interface`/`type` declarations** (`:19` `User` … `:2829` `RunSocketLike`) interleaved with the client (`realApi` `:3025-4089`, `api` `:4093`), nine client helpers (`:2839-2934`), and two contract constants that live among the types because types derive from them (`DEFAULT_AUTOPILOT_LABEL` `:981`; `RATE_LIMIT_SOURCES` `:2137`, the source of `RateLimitSource = (typeof RATE_LIMIT_SOURCES)[number]` `:2138`). **207 files** import from `lib/api` (measured: `git grep -l -E "from ['\"](\.\./)*lib/api['\"]|from ['\"]\./api['\"]" -- 'web/src/**/*.ts' 'web/src/**/*.tsx'`; the epic's 161 was an under-count), 43 of them type-only. Every DTO edit diffs against the client and vice versa.
2. **W5** — `web/src/pages/AdminSettings.tsx` (2499 lines) = one shell (`AdminSettings()` `:103-456`, which renders three inline `<Card>`s: `vault-migration` `:278`, `forge-labels` `:293`, `sso` `:391`) plus **ten named card components** (`:457-2498`) that share nothing with each other but the `settings`/`sources`/`onSaved` props the shell passes them (`:368-445`). 13 `<Card` renders in total, matching the epic's count; 10 of them are movable components, 3 are shell JSX over shell state.
3. **W8** — `web/src/mocks/data.ts` (5434 lines, 75 exports, 18 importers) is already banner-sectioned into **30 `// ── <domain> ──` sections** (`:57` Users … `:5369` Build info) over a prelude of time helpers (`NOW` `:44`, `minsAgo`/`secsAgo`/`daysAgo`/`minsAhead` `:45-55`). Its cross-section reference graph was measured for this PRD (script in the epic's evidence): **acyclic**, every code reference points forward except two hoisted function declarations (`SAMPLE_PLAN` `:4317`, `SEEDED_PLAN` `:4334`, defined in the "Other users' active runs" section `:4194` and called from the Runs section `:3120,:3231,:3433,:3512,:3587,:3641` and, forward, from the histories section `:4440,:4532`); the other apparent back-edges (`:135`, `:204-205`, `:265`, `:465`, `:1356`, `:1721`, `:2857`) are comment mentions. So a per-domain split has a dependency order and no cycle to break.

## Solution

Three same-behavior file splits, one milestone each, file-disjoint so they can run as three parallel coder invocations. **Pure motion**: declarations move verbatim with their doc comments; the only new text is import/re-export/barrel scaffolding. Importers stay byte-identical via re-exports (207 for `api.ts`, 18 for `data.ts`). Existing tests pass unmodified, with **one named exception** (M3's acyclic guard, which the split would otherwise both crash and silently bypass — see M3).

**Out of scope** (epic "Later / needs decision"): W6 `RunView.tsx`, W7 `mockApi.ts`, W9 `Board.tsx`. W7 in particular stays a single object literal typed `typeof realApi`; this PRD does not touch it.

## Decision Log

- **D1 — re-export, do not migrate importers.** 207 + 18 import sites stay byte-identical, which is what makes each milestone reviewable as motion. Pointing the mock graph at `apiTypes.ts` directly (shrinking the acyclic guard's surface) is a possible later sweep, not this PRD.
- **D2 — `web/src/pages/adminSettings/` is the first subdirectory under `web/src/pages/`.** `web/src` has exactly five flat directories today (`auth`, `components`, `lib`, `mocks`, `pages`). A settings card is page-private, not a reusable component, so `components/` is the wrong home; ten `components/AdminXxxCard.tsx` files with a name prefix would be a directory in denial. Lower-camel directory name, matching `lib/` module naming.
- **D3 — a directory barrel for `data`, not a rename.** Keeps every specifier; `index.ts` is star re-exports only. Star re-exports are knip-clean (each domain module's export is used by an importer through the barrel exactly as before); a domain export used by nothing was already a finding on `main`.
- **D4 — the acyclic guard is strengthened, not patched.** Adding `data/*.ts` names to `MOCK_FILES` would fix the crash and leave the `../../lib/api` blind spot; the walk + path resolution closes both, and the positive control is what proves the closure (an instrument that cannot produce the disconfirming answer is not evidence).
- **D5 — the two contract constants move with the types.** `RATE_LIMIT_SOURCES` is the source of a union type; leaving it in `api.ts` would force `apiTypes.ts` to import from `api.ts` (a cycle, even as `import type`). `DEFAULT_AUTOPILOT_LABEL` is a contract default beside its `AppSettings` type. Both are value re-exported from `api.ts`.
- **D6 — `NOW` is the only visibility change.** Everything else keeps its export status; the split must not add `export` anywhere else (knip would report a new unused export at `error` anyway).
- **D7 — W7 (`mockApi.ts`) stays out.** Its single object literal is what `api: typeof realApi` typechecks; splitting it is its own decision in the epic.

## Risks & mitigations

- **ESM cycle / TDZ between `data/` modules.** The graph is measured acyclic; the two hoisted functions are placed explicitly. If a regroup introduces a cycle, a module-level `const` reading a sibling's binding throws at import, and `data.test.ts`/`data.realism.test.ts` (which load the barrel) go red — a loud failure, not a silent one. Keep the barrel's `export *` order equal to the dependency order anyway.
- **knip and `export type *`.** Expected clean (knip resolves star re-exports); the M1 fallback is an explicit list, never `ignore`.
- **`vite` directory-index resolution** for `./data` is standard, but the bundle is outside `task gate:web` — hence the explicit mock build in M3.
- **`AdminSettings.tsx` cards that close over shell state.** The measured shell→card contract is `settings={saved}`, `sources={sources}`, `onSaved={applyResponse}` (`:368-445`) and `UpdatesSettingsCard`/`AgentSourceSettingsCard` take nothing; the three inline cards that DO read shell state (`uziLabel`/`autopilotLabel` form fields, `oidcStatus`) stay in the shell by design. If a card turns out to reach shell state the grep missed, keep it in the shell and say so in the PR rather than threading new props (that would no longer be motion).
- **In-flight overlap: none.** #954 (running) and #956 (tonight's sweep) are `api/` only; the refactor freeze keeps every other schedule paused. The four doc files this PRD edits (`ARCHITECTURE.md`, `specs/ai.md`, `docs/dev-conventions.md`, `.claude/rules/web.md`) are not touched by either, nor is `api/internal/uzidocs/embed/`.
- **Offline worker.** Nothing here needs the open internet; every fact is in-repo.
