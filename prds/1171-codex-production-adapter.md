## Problem and outcome

The repository can store Codex credentials and launch one isolated Codex process root, but the live worker still constructs only `ClaudeHarness`/`ClaudeAdviceHarness`. It has no stock app-server transport, worker-owned callback authority, synchronous child-thread delegation, all-roots registry, matching-epoch safety permit, Codex credential-refresh bridge, or production Codex prompt renderer. Consequently no run can safely execute on Codex, and M4 conformance plus M5 routing remain blocked.

Deliver the complete **production execution spine** for a Codex-selected, already-bound claim:

- `CodexHarness` and `CodexAdviceHarness` implement the neutral contracts using the pinned stock app-server and M3a launcher;
- worker-owned callbacks, not Codex native tools/roles/hooks/MCP, own shell, file/patch, skills, workflow signals and synchronous delegation;
- one immutable per-run/local-execution-epoch registry owns every provider and command supervisor root, callback and launch reservation;
- the runner holds an unforgeable matching-epoch safety permit across every durability/publication sink;
- provider roots are OS-isolated from model-authorized command/file effects, so “credential-free” means inaccessible rather than merely absent from a command's environment;
- subscription refresh goes through M1's API-owned coordination/recovery state machine, while API-key runs never silently fall back to subscription credentials or vice versa;
- Claude construction, event projection, cleanup timing, prompts and tests retain D0 behavior.

This child may make a **dark internal Codex-bound claim** executable in tests and in the maintainer-only live probe. M5 still owns `runs.harness`, public/manual/schedule selection, old-worker claim compatibility, model/default UI and broad run-kind routing. Saving a Codex credential must remain insufficient to create a Codex run through today's public paths.

## Frozen boundaries and non-goals

- Stock app-server only. Disable native environments, native agents, native shell/file tools, native web, MCP, plugins/apps and hooks. Provision the canonical project explicitly `untrusted`, set `project_doc_max_bytes = 0`, and use no hook-trust bypass. Loopback MCP, native role TOML and SDK-only root streaming are rejected designs.
- Runtime callback arguments and model text are untrusted data. Authority comes only from worker-owned immutable run, credential claim epoch, local execution epoch, thread, turn, role, phase, tool/skill and root-registry state. Unknown/stale origins and malformed/unsupported messages fail closed.
- The API `codex_claim_epoch` (credential capability/reclaim authority) and adapter-local execution epoch (callback/root closure and permit matching) are distinct branded domains. Never compare, copy or substitute them. A new claim constructs a new execution registry; a safety permit matches only its held local execution epoch.
- Root-only workflow signals remain root-only. A subagent cannot `submit_plan` or `signal_done`; unknown/nested delegation is denied. Display attribution never grants signal authority.
- Every Codex model effect process is a registered M3a supervisor root. Never infer run safety from app-server exit, process-group kill, one root's `ECHILD`, a callback reply, a name/glob or process inspection outside recorded ownership. While model-authorized command/file callbacks are admitted, they must be unable to read any provider root's argv, environment, descriptors, HOME/CODEX_HOME/XDG/auth/session state, or another run's state through `/proc`, `/data`, guessed paths or enumeration. Same uid plus mode 0700 is not evidence; establish a distinct OS identity/namespace or an equivalently enforced isolation boundary, and stop if it cannot be proven.
- Closing model/callback admission may leave only a distinct trusted boundary-action lane. Every subprocess a permitted checkpoint/git/finalize/recovery action starts reserves owned process state before spawn; the permit remains held until the action and all children actually settle. Timeout/error never returns while an action child runs, and incomplete settlement poisons the epoch. No direct `child_process` bypass is allowed.
- Subscription and API-key credentials are immutable private construction inputs with no fallback. Provider roots receive only their selected credential; command roots are credential-free. No model-visible token, refresh/login blob, run capability, forge PAT, private endpoint or worker environment.
- Credential-free means inaccessible, not merely omitted from an environment. Provider and command roots must be tested concurrently with secret-shaped canaries through guessed and enumerated `/proc` and state paths.
- The shared advice ceiling permits isolated pure in-memory calculation only. Advice exposes no credential operation to the model and receives no workspace or general run callback registry. Its trusted transport may receive only the narrow immutable provider-auth/refresh bridge needed for its selected credential, under the same M1 authority, generation, persistence and disposal rules. If that authority is unavailable, refresh fails closed. Claude advice remains tool-less; this child adds no Claude calculator.
- The production builder fixes the vendor endpoint, provider name, credential env key, binary and supervisor target. None comes from a claim, model, repo, saved label or callback. Localhost/fake-provider injection exists only in a non-exported test/integration composition unreachable from production routing.
- Never log raw app-server frames, auth callback bodies/replies, transport stderr, HTTP bodies, tokens/capabilities or attacker-controlled values in error strings. Diagnostics are static/bounded/redacted. Park/restart/final disposal removes provider auth/cache material while preserving only credential-free session state (or proves pinned Codex wrote none); every recreated root requires a fresh API-authorized committed token/generation release.
- Preserve Claude byte-for-byte at its construction, prompt/render, event/wire, error-ordering, clean-EOF, cleanup and callback boundaries. Do not “improve” inherited Claude behavior in this child.
- No `runs.harness`, `run_usage.harness`, pricing table, public picker/default/schedule/CLI flag, broad run-kind routing, chat-on-Codex, egress/chart, image tag, deployment, release or M4's exhaustive adversarial clause matrix.
- No production `.github/workflows/**` change, including validation. Any repeatable recipe belongs in root `Taskfile.yml`. No real secrets; assemble secret-shaped fixtures at runtime and run `task scan:secrets` with its canaries detected.
- Run `task scan:secrets` with canaries detected before every milestone commit/checkpoint that introduces or changes credential/redaction/capability-shaped fixtures; a clean final tree cannot clear a forbidden literal retained in an earlier commit.
- Test containers use exact invocation-owned names outside `uzi-` (for example `cdr-*` or `aud-*`) and cleanup removes only that exact resource. Never run `docker compose down` from a worktree, never pass `-p uzi` to `down`, never add `-v`, never filter/glob `uzi-*`, and leave unattributed containers/processes untouched.

## Risks and stop conditions

- **Authority drift:** app-server/runtime protocol changes could bypass callback identity or builder restrictions. Pin to 0.153.2 and fail closed on unknown identity/authority-bearing messages; M4 later expands the adversarial matrix.
- **Cross-root credential read:** provider and command roots currently share the runner uid, so sparse command env plus mode-0700 homes is insufficient. M3 must establish and prove an OS boundary before model-authorized command/file callbacks coexist with a credentialed provider root.
- **False cleanup confidence:** a clean provider root can coexist with a live command root or accepted callback. Aggregate recorded ownership only; any incomplete root/reservation/callback poisons the epoch and blocks sinks.
- **Boundary child escape:** the permitted checkpoint/git/finalize action itself can spawn after the pre-action reap. Track that trusted lane and hold the permit through actual child settlement; timeout never means clean.
- **Refresh race or lost provider outcome:** CAS alone is insufficient. Use M1's short operation coordination, durable intent, generation reconciliation and protected recovery. Stop if the real callback cannot supply/retain the required operation/generation state without trusting model/provider hints as authority.
- **Resume state mixes session and auth:** a fresh M3a home cannot find a prior session, while preserving the full home can retain stale credentials. Persist only a proven credential-free session subset and freshly re-authorize auth per root; stop if pinned Codex cannot separate them safely.
