## Problem

`runs.kind` has eight values — `issue`, `ci_fix`, `chat`, `judge`, `self_improve`, `prompt`, `task`, `mr_rework`, in that DB order (`api/internal/store/migrations/00167_run_mr_rework_kind.sql:19`) — and **no single source of truth outside the DB CHECK**. Six migrations define `runs_kind_check` (00043 creates it inline, auto-named; 00053, 00058, 00104, 00134, 00167 each DROP+ADD it; the epic's "10" was an overcount, 16 migrations *reference* a kind literal), and each rewrites the companion `runs_kind_shape` CHECK (`00167:22-30`), which is a real per-kind property table (has issue / has pipeline / has branch / repo-less) that **no Go or TS code can read**.

**Go (api).** The set is spelled as **nine constants across two packages**: `workersvc.RunKindIssue`/`RunKindCIFix` (`workersvc/ci_fix.go:18-19`), `RunKindChat` (`chat.go:24`), `RunKindJudge`/`RunKindSelfImprove`/`RunKindPrompt`/`RunKindTask` (`judge.go:23-35` — `RunKindTask` lives in `judge.go`), `RunKindMRRework` (`mr_rework.go:20`), and `slacksvc.runKindChat` (`slacksvc/chat_open.go:16`, whose own comment says "it matches `workersvc.RunKindChat`" — nothing enforces it). The constants are **bypassed by bare literals in their own package** (`workersvc/prd_done_path.go:39`, `report_only.go:24`) and by every comparison outside it (`handler/workers.go:326`, `handler/workers.go:1188`, `slacksvc/notifier.go:425`, `cmd/uzi/handoff.go:385`, `cmd/uzi/run.go:781`, `cmd/uzi/tui_steer.go:89` — the epic's "CLI has zero kind branching" is refuted: three sites). `git grep -n -P '[Kk]ind\s*[!=]=\s*"(issue|ci_fix|chat|judge|self_improve|prompt|task|mr_rework)"' -- 'api/**/*.go' ':!*_test.go' ':!*.sql.go'` finds those **8 bare-literal comparisons**; with the sites that go through the constants, the re-derivation enumerated **28 non-test, non-generated branch sites** (the epic's "~20" was an undercount; the 28 is a read-and-classified tally, not a single grep). **No Go test pins the set** to the migration. Three present-tense doc comments enumerate it wrongly: `apitypes/run.go:44-45` lists seven (no `mr_rework`), `issuedraft/finding.go:20` four, `issuedraft/issuedraft.go:56` two.

**The one Go property registry has an unpinned twin.** `judgeEligibleKinds` (`workersvc/judge_enqueue.go:23`, `{issue, ci_fix}`, read at `judge_enqueue.go:67` and `judge_read.go:224`) is duplicated as `JUDGE_ELIGIBLE_KINDS` in `web/src/pages/RunView.tsx:2150` (read at `:2240`). No test, lint or nudge relates them; a ninth judge-eligible kind added on one side silently hides the judge panel on the other. Likewise `handler/workers.go:326` (`isPlanningPhase`, `kind == "chat" || kind == "judge"`) is a hand-kept pair with `ListRunsForUser`'s `NOT IN ('chat','judge')` (`store/queries/runtime.sql:481`); its comment says so.

**Agent (worker).** The set exists and is pinned: `RUN_KINDS`/`RunKind` (`agent/src/protocol.ts:226-227`) with `agent/test/run-kind-db-parity.test.ts` reading the live migration. But per-kind *behaviour* is spread across roughly **30 branch sites in `runner.ts`, `sdk-executor.ts`, `executor.ts`, `prompt.ts` and `worker.ts`, 21 of them in `runner.ts`** (20 `claim.kind ===`/`!==` comparisons — `git grep -c -P 'claim\.kind\s*(===|!==)' -- agent/src/runner.ts` — plus the `:860` `?? "issue"` default site) — unchanged by #949's split, which moved code between methods inside the same file. Three clusters are pure per-kind tables written as if-chains: **branch naming** (`runner.ts:2893/:2906/:2922/:2939/:2959`, in `runnerCloneForClaim`), **MR title fallback** (`:3430/:3436/:3440/:3445`), **MR body + whether it `Closes` the issue** (`:3475/:3488/:3499/:3517/:3534`). The `?? "issue"` default for an absent `claim.kind` is re-applied at four sites (`runner.ts:860`, `:2167`, `prompt.ts:264`, `sdk-executor.ts:874`), each with its own comment. The only helper is the file-private `isMrReworkKind` (`prompt.ts:236`). **`self_improve` has no runner-level characterization test**: `git grep -c -F 'kind: "self_improve"' -- agent/test` matches nothing, so `runner.ts:1008` (dogfood evidence), `:2906` (branch) and `:3475` (MR body) would move with nothing watching.

The epic's "11 web sites" is numerically near but structurally wrong: a `.kind ===` sweep over non-test `web/src` (`git grep -c -P '\.kind\s*===' -- web/src ':!*.test.*'`) finds **83** comparison sites, of which **4** are run kinds — the rest are `RunMessage.kind`, worker/secret/badge/notification/input kinds, and two decoy unions (`RunTriggerSource` `apiTypes.ts:1699-1712`, 13 members overlapping the kind names; `ScheduleTarget` `:1208`, where `sweep` is not a kind).

**Net.** Adding a kind today is O(sites) with no compiler help anywhere but the agent's union, and no test that names what was missed on the Go or web side.

## Solution

**One leaf Go package, one shared hand-authored fixture, per-side tables pinned to the source of truth.** Behaviour-preserving throughout: every value in a table is lifted verbatim from the branch it replaces.

### `api/internal/runkind` (new, leaf: stdlib imports only, zero `internal/`)

```go
const ( Issue = "issue"; CIFix = "ci_fix"; Chat = "chat"; Judge = "judge"
        SelfImprove = "self_improve"; Prompt = "prompt"; Task = "task"; MRRework = "mr_rework" )
func All() []string            // the eight, in DB CHECK order
func JudgeEligible(kind string) bool   // {issue, ci_fix} — moves here from workersvc.judgeEligibleKinds
func Listed(kind string) bool          // all but chat, judge — the run-list / planning-capable set
```

Untyped string constants (D1): a drop-in for the nine existing ones, so every comparison compiles unchanged after the rename. **No `Valid()`**: nothing in `api/` validates a kind string today (every create path assigns a SQL literal; no handler accepts a kind from the wire), so a validator would have no consumer — `deadcode:api` reports an exported uncalled function — and adding a call site would be a new rejection path, i.e. a behaviour change. It arrives with its first real validator, not before. Package doc (`doc.go`) is **the "adding a run kind" checklist** (M5).

Three pins, each a Go test in the package:

| test | reads | asserts |
|---|---|---|
| `runkind_migration_test.go` | `../store/migrations/*.sql` — Up section only (slice before `-- +goose Down`), highest-numbered file whose Up redefines `runs_kind_check`, regex anchored on the constraint name — the Go twin of `agent/test/run-kind-db-parity.test.ts:14-82`, same algorithm, same three diagnostic messages | set-equality with `All()` in both directions, plus order |
| `runkind_sql_test.go` | `../store/queries/runtime.sql`, the four `-- name:` blocks that carry the byte-identical filter today: `CountInProgressRunsForUser` (`:303`), `ListRunsForUser` (`:481`), `ListActiveRunsAll` (`:519`), `SweepRunningTimeout` (`:2054`) | each block's `kind NOT IN (...)` literal set equals `{k ∈ All() : !Listed(k)}` — all four, not a representative one, so a divergence introduced in any sibling is red |
| `runkind_fixture_test.go` | `../../../fixtures/run-kinds/registry.json` | `kinds` equals `All()` (order included); `judge_eligible` equals `{k : JudgeEligible(k)}` |

The first two read files **inside** the `api/` module, so Go's test cache rechecks them; the third reads above the module and needs `-count=1` (`task test:api` carries it — the `fixtures/run-usage` README's asymmetry, restated in the new fixture's README).

### `fixtures/run-kinds/registry.json` + `README.md` (new)

```json
{ "kinds": ["issue", "ci_fix", "chat", "judge", "self_improve", "prompt", "task", "mr_rework"],
  "judge_eligible": ["issue", "ci_fix"] }
```

Hand-authored, never generated, no `-update` flag on either side — the `fixtures/agent-template-drift` shape. **A property enters the fixture only when it has a production consumer on both the Go and web side** (D3); today that is judge eligibility alone. Two readers, **both tests**: the Go fixture test above and `web/src/lib/runKindContract.test.ts`. The fixture is never read at runtime — production `web` cannot reach a repo-root file, so `isJudgeEligible` hard-codes its set and the contract test is what pins it. README carries the do-not-tidy list, the two readers, and the `-count=1` asymmetry.

Why a fixture bridges Go↔web rather than web reading a source file the way the agent test does: `web/` cannot import `agent/src/protocol.ts` (separate npm package and tsconfig; no cross-package path alias), and reading `api/internal/runkind/runkind.go` from a vitest would be a regex over Go source, which is exactly the third-copy-by-another-name the `agent-template-drift` README argues against. The migrations are the source of truth for the *set*, and the agent test already reads them; for a *property* there is no source file to read, only a table someone hand-authored — so it is authored once, in the fixture.

### `web/src/lib/runKind.ts` (new)

`RUN_KINDS` (`as const`, DB order) and `RunKind`; `runKindLabel` **moved verbatim** from `RunIssueRef.tsx:9-19`; `isJudgeEligible(kind: string)` with its set hard-coded (see above). Consumers land in the same commit (knip `exports: error`, `web/knip.jsonc`).

### `agent/src/run-kind.ts` (new)

`RUN_KINDS` stays in `protocol.ts` (it is the wire type); this module imports it and adds:

- `resolveRunKind(kind: RunKind | undefined): RunKind` — the `?? "issue"` default, once, with the four sites' comments folded into one.
- `RUN_KIND_PROFILES: Record<RunKind, RunKindProfile>` — the TypeScript `Record` over the union is the exhaustiveness check: a ninth kind fails `typecheck:agent` until it has a row. **All three per-kind fields are optional, and `undefined` means "take today's issue path"** — the same fall-through the if-chains end in, so the issue arm is never moved into a row:
  - `cloneBranch?: (claim, runId) => { branch, slug } | undefined` — undefined (no row, or a row returning undefined) ⇒ `createOrAttachRunnerClone` keyed on `issue_iid`, today's `runner.ts:2981`. `task`/`mr_rework` rows keep their throw-on-missing-`claim.branch`.
  - `mrTitle?: (claim) => string | undefined` — undefined ⇒ the `:3446` fallback.
  - `mrBody?: (claim, ctx) => string | undefined` with `closesIssue: boolean` on the row — undefined ⇒ the issue body after `:3534`, which **stays as the fall-through in `mrDescription`** because it is the richest arm (the `scopeCapped` variant, the appended gates section, the `Closes #<iid>` line) and no other arm has any of it. The five non-issue arms need different inputs today (`selfImproveSection`, `promptGuardSection`, `branch`, `base_branch`, the repo marker), so `ctx` is one explicit bag `{ branch, baseBranch, repoMarker, selfImproveSection?, promptGuardSection? }` the caller assembles exactly as the current code does before the chain; the implementer names the fields from the arms, not from this sentence.
  - **The `ci_fix` rows preserve their `&& claim.pipeline` guard.** All three ci_fix arms are gated `kind === "ci_fix" && claim.pipeline` today (`:2893`, `:3430`, `:3488`) and `pipeline` is optional on the claim, so a pipeline-less ci_fix claim falls through to the issue path. Each ci_fix row therefore returns `undefined` when `claim.pipeline` is absent — never dereferences it — and the fall-through is byte-identical. (Not a live case: the DB shape CHECK requires `pipeline_id` for ci_fix. It is the defensive path, and behaviour-preserving means the defensive path too.)
  - `chat` and `judge` get rows (the `Record` demands them) with no functions, i.e. the fall-through; they never reach `RunRunner` today (chat is a separate lane, `client.ts:145`/`worker.ts:247`; judge is dispatched at `worker.ts:188`) and the rows preserve that (D8).

**Stays as branches, by design (D6):** `runner.ts:860/:936/:1008/:1084/:1097/:1501/:2277` (terminal/publish/gate behaviour — ADR-0279 §2 forbids broadening the issue-kind gate, and each carries its own zero-diff / fail-open reasoning), every `sdk-executor.ts`/`executor.ts`/`prompt.ts`/`worker.ts` site (they are kind-specific capability gates, already typed by the union), and the `worker.ts:186-190` dispatch order (`review_target_run_id` before `kind`, which must be preserved verbatim).

### Go migration (M2), all mechanical

Delete the nine constants and `judgeEligibleKinds`; repoint every user to `runkind.*`; replace the bare literals at the 28 branch sites and the 3 CLI sites; `isPlanningPhase` becomes `!runkind.Listed(kind)`; fix the three stale comments. **SQL is untouched** (D4): the 11 INSERT literals and 44 filters in `store/queries/*.sql` stay, because sqlc cannot consume Go constants and the DB CHECK is the DB's own validator — the migration test is what links the two.

## Decision Log

- **D1 — untyped string constants, no Go enum type.** sqlc rows type `Kind` as `string`, `.golangci.yml` enables no `exhaustive` linter, and every consumer already compares strings; a `type Kind string` would force a conversion at each of the 28 sites for no gate-visible gain and stop being a drop-in. The TypeScript side gets the typing for free (`RunKind` union + `Record`). Revisit if `exhaustive` is ever enabled.
- **D2 — every side pins to the source of truth, never Go against TS directly.** Go and agent each parse the migrations (agent already does; Go gets the twin); web reads the fixture; the fixture is pinned to the migrations through Go. A direct Go-vs-TS diff would say only *that* they differ, never *which* drifted, and would make `npm test` need a Go toolchain (`fixtures/run-usage/README.md`).
- **D3 — the fixture carries only cross-side properties.** Today: the kind list and `judge_eligible`. `Listed` is Go+SQL and is pinned by parsing `runtime.sql` instead. `has_issue`/`repo_less`/priority demotion/docker-allowlist exemption stay where they are (SQL): no Go or TS consumer would collapse into them — `claim_assembly.go:31` tests `judge` specifically and must keep doing so, and `00113_fleet_aware_claim.sql:25` exempts `judge` alone "so a future repo-less kind fail-closes" by design.
- **D4 — SQL untouched.** 11 INSERT literals and 44 filters keep their literals; the CHECK is the DB's own validator; `runkind_migration_test.go` is what makes a Go/DB divergence red.
- **D5 — `Run.kind` stays `string`; `apiTypes.ts` is not in this diff.** #982 edits the `Run` interface concurrently; narrowing `Run.kind` to `RunKind` (and fixing its three-kind doc comment at `apiTypes.ts:1723`) is a one-line follow-up after #982 merges. Web helpers therefore take `string`, the `canToggleMrRework` shape.
- **D6 — kind-specific logic stays as branches; the registry holds properties.** A site enters a table only when it is a pure per-kind value (branch/title/body templates, the default, judge eligibility, the listed set). Task lifecycle (5 Go sites), claim-assembly extras (3), chat guards (5), issue-only clamps (4), token binding, notification suppression, and the runner's seven terminal/publish/gate sites stay as typed-constant comparisons. ADR-0279 §2 is the standing reason not to broaden the issue-kind gates.
- **D7 — characterization before motion on the agent (M4a precedes M4b), and the agent milestone goes last.** The three unpinned `self_improve` runner sites are the exact gap the epic's safety contract names. M4 is the only milestone that moves code rather than renaming or adding, so it sits after the landable M1–M3 slice; the architect review proposed splitting it into its own issue, and the answer is the scope ceiling instead — same isolation, one PR if it goes well.
- **D8 — off-lane kinds get profile rows, and the fall-through is preserved.** `chat`/`judge` rows exist because the `Record` demands them and because their absence would be the silent case; their `cloneBranch`/`mrTitle` are undefined, which reproduces today's issue fall-through byte-for-byte should either ever reach the run lane.
- **D9 — `prompt` is never mocked in `web/` (30 mock runs, 7 of 8 kinds).** Finding, not scope: mock content is behaviour in mock mode, not a refactor. Filed in the epic's Declined/honest-gaps list.

## Risks & mitigations

- **A wrong mapping compiles and passes.** `Listed` replaces a two-literal check in one place; `JudgeEligible` is covered by the enqueue/read tests; every other Go site is a same-comparison rename. The reviewer checks each M2 hunk against "same literal, same operator".
- **Agent templates drift by a byte.** MR title/body strings are pinned by `runner-push-mr`, `runner-task`, `runner-mr-rework`, `runner-prompt` tests plus M4a; SC4's byte-identical rule makes any assertion edit a red flag. Reviewer diffs each template side by side with the arm it replaced.
- **knip reddens a module shipped ahead of its consumers.** Land `run-kind.ts`/`runKind.ts` and their first consumer in one commit.
- **Ratchet (`whole-files: true`)** on every touched Go file: run `task lint:api` per commit.
- **`-count=1`** on any fixture-only edit (gate carries it; the README says why).
- **Merge overlap** with #982 avoided by D5; with P14 by sequencing (P14 authored against post-#983 main).
- **Sweep traps.** `git grep -E '\.kind\s*…'` returns **0** on this host (`\s` is not POSIX ERE): use `-P`; use `-F` for literals; the 75 `.kind` comparison sites in `web/src` are dominated by message kinds, and `RunTriggerSource`/`ScheduleTarget` reuse the kind names — classify by the receiver's type, not the literal.
